# RPG系统深化：实施边界

2026-11-07 UTC。承接用户八点补充，先把系统做成能实际游玩的闭环，内容保持MVP。

1. 时间与休息：战役库存时钟为持久时间源，WorldTime为24小时/日期投影。休息选游戏小时，数秒仅为可中断的表现准备；成功后真实推进状态、涂层、采集再生与NPC服务时段。拒绝敌人附近和有害状态下休息；消耗真实食品/水，保留粗食兜底，不免费完全恢复。
2. 物资与经济：少量原料采集点接入当前地图；制造贯通原料、补给、武器弹药与药剂。一个有限库存商人验证按UID买卖，装备可拆解为原料或以材料强化，保留同UID、涂层与快捷绑定。物品交易、产出、强化均经InventoryService原子边界，容量/失效/材料不足失败不部分扣款。
3. 武器：Resource描述武器动作序列和武技；实例状态放角色执行器。玩家逐次按键推进连击，普通/重击、取消窗口、体力与动作承诺共用；刀、矛、杖有明确节奏，弓箭验证弹药与物理投射。武技单独走武器要求、体力、冷却及真实弹药，不伪装成消耗法力的法术，仍用同一13槽绑定。
4. 法阵与增益：灰河谷法阵使用较长存续与时间预算，组合扣减剩余时间，失败只退实际预留时间，不续满。原型模式保留旧规则以维护迁移。食物和药剂可提供有来源、互斥组和期限的增益，不重复构建Buff系统；休息后不能续满。
5. 敌人：按可见局面选动作，加入视线、等待/恢复、对玩家布阵施压、近战破防/武器差异和远程保持距离；保留真实资源和受击规则，不读取不可见的玩家背包或免费补条件。
6. 内容：保留现有区域、任务、解谜；仅添加验证上述服务所需的采集、交易、训练/书籍入口，不大批扩地图剧情。
7. 知识与成长：原属性成长继续；武技通过有限的训练师教学与技能书验证。知识只负责解锁，装备/库存负责执行条件；学习失败不扣款、不吞书。配方/法术旧发现兼容，不整包回退旧技能。
8. 验证：各链请求/失败/保存重进与真实键鼠验证；正常AI代表性战斗。最后干净提交归档首次导入、全量回归、推送PR合并，Actions继续停用。

Godot依据：4.6官方Scene organization与Node alternatives，Resource共享定义、RefCounted纯服务、Node负责场景与输入，组合根注入依赖。UI提交请求，不发展第二份库存、绑定或进度权威。
