## 已实现的边界

| 状态 | 权威与恢复方式 |
|---|---|
| 定时Buff/异常 | `BuffManager`保存可信定义路径、运行持续时间、剩余时间、层数、周期相位、来源ID与施加时强度；不回放施加/净化事件 |
| 控制与元素积累 | 继续使用原控制恢复与`StatusBuildup`，个人状态跨区保留；未加载时间按真实到期边界推进 |
| 法术与武技冷却 | `SkillManager`保存槽冷却和共用动作冷却/总时长；武技保留原持久时钟期限；进镇与读档不清零 |
| 涂层/喷剂/装备 | 仍由`InventoryService`的具体UID与实例属性持有，不复制到Buff存档 |
| 区域瞬态 | 法阵、区域临时能量、瞄准、引导、准备、后摇机会不恢复，不制造永久库存 |

`CampaignSession`显式注入来源ID查询。区域全部挂载后才结算未加载期间的周期伤害，避免首个死亡错误触发整区清场；正常命中、经验、遗骸、真实装备UID沿原链结算。F9与重新打开进程共用个人状态恢复。旧v7只导入当时真正保存的食品/药剂剩余时间，不能凭空恢复旧版本没保存的异常。

行囊以UID协调现有物品控件；无关NPC库存变化不会销毁悬停/按下的按钮。详情只在所选实物、位置、可访问容器或装备确实变化时重建，数量编辑与滚动不因无关通知丢失。纸娃娃同时监听真实装备与背包挂载状态。动作提交仍校验当前来源、数量、距离与权限。

新旅程使用现有槽3，不增加另一套战役状态。产品内确认后，`SaveRepository.start_new`先保留原始主/备份/临时文件和最新内存快照，再暂存全新主/备份，建立新备份后最后替换主档；普通I/O失败返回失败并恢复旧备份。`SaveManager`阻止旧场景继续写回，`CampaignGame`重建入口场景。断电级多文件原子性不在本轮故障注入证明范围；归档保留旧文件供恢复。归档不会自动被F9加载。
