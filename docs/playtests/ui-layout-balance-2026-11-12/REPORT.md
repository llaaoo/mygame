# 模块比例、对齐与小窗口布局整理

基线 `a0cea3fcc3a2ced32624b011d5742090bce8785e`。本轮调整真实Godot界面的尺寸和布局，沿用现有配色、实物、按键与表现资源；没有新增玩法或更改存档格式。

## 观察与修改

| 观察到的问题 | 最终处理 |
|---|---|
| 穿戴列固定210px，角色、九槽和状态挤成长列；列表拿走过多宽度 | 穿戴/实物/详情以26/34/40比例分配，先满足可读最小宽度；足够宽时装备槽成对排布，窄屏仍可滚动 |
| 详情操作因文本宽度落成零散行 | 主操作使用等宽两列，与详情边缘对齐；保持独立于阅读滚动和绑定选择 |
| 宽屏内容横跨过长，区域比例越拉越散 | 统一管理页最大工作宽度1600逻辑像素；不缩放世界、HUD或文字 |
| 制造页120px侧栏把短说明挤成碎行 | 共用侧栏加宽到176/208px；列表/详情按36/64比例分配 |
| 技艺目录固定260px，快捷槽靠左且与页面重心脱节 | 目录/详情按34/66比例分配，13个真实绑定槽与提示居中 |
| 成长树锚在画布左上，分支和说明偏窄 | 加宽两侧，树水平居中；节点高度依据实际字体，连线读取真实节点边缘；属性阅读区居中 |
| 960×540、125%字的制造页底部出屏 | 移除列表/详情强制160px高度的限制，允许收缩到80px后滚动；正文和操作目标不缩小 |
| 交易数量框像整行文本编辑器，辅助说明却挤在右侧 | 数量框160px、详情按钮280px；纯辅助按钮靠右，说明文字保留正常阅读宽度 |
| 窄屏标题和导航争抢空间 | 导航省去常驻键位后缀，当前绑定保留于悬停，原快捷键仍有效 |

HUD检查沿用已有分区，没有为填满空间增加常驻信息。没有用假物品、假Perk或假进度填补真实内容较少时的留白。小窗口成长树保留独立横/纵滚动，部分节点需要滚动查看，未缩小文字或隐藏节点。
