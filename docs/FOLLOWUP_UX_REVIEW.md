# 智能施法与操作衔接复查

2026-11-08，基线`43c14dab138139b3bfd168ff6e792da379b90718`。本轮是审查与复现，以下问题均待修；没有改变玩法或数值。结论：优先补上智能模式与既有地面组合的衔接，以及改绑后的输入目标恢复，再处理滚轮与反馈层级。

## P1：智能模式阻断既有水面调谐路径

受控领域复现：已掌握水引、调谐与`terrain_water_focus`，实际施放水引生成脚下`wet`水面，最近元素变为`water`。此时智能E槽的Shift调谐显示“这个动作没有当前元素的形式”，请求拒绝、未扣MP。手动将同槽固定为`basic`（纯粹凝神），同一水面上的Shift调谐立即可用，实际消费8 MP并获得`flow_attunement`（流息）。没有注入水面或直接设置最近元素。

现有组合能执行，但默认智能路径缺少它的映射。`SpellFormAssist.resolve_automatic`只匹配介质的单一元素，水面组合通过共享基础动作与地面规则实现，二者未衔接。此前96项回归没有覆盖这条智能模式交叉路径，不能据旧成绩排除此问题。

建议：将地面组合接入明确的上下文形式/规则映射，继续由原组合规则校验已学知识、Shift、真实地表与消费；条件消失时明确拒绝。不要把缺少映射改成随意回退到免费基础增益。随后覆盖水、冰、火、导电与毒地的矩阵；本轮只实测了水面，不推断其余全部失败。

关联：`gameplay/quickslots/spell_form_assist.gd:23`、`content/combinations/terrain_water_focus.tres`。原始领域结果与完整临时探针源码在[证据JSON](validation/followup_ux_review.json)中。

## P1：快捷槽改成物品后，世界滚轮仍锁在旧槽

原生输入复现：先使用E的投射，再在K把E改为饮用水；随后在M明确选择5槽的火石阵并确认。此时`last_spell_source=quick_e`、`wheel.last_source=slot_4`。在世界中滚动，5槽仍为火石阵，也没有切换反馈。再按一次5，即使该次施法因缺火石拒绝，滚轮就能正常把5槽改成霜盐阵。

原因是输入处理只在旧来源为空时才采用轮盘来源；旧来源已不适用时直接返回，未尝试有效候选。玩家很难理解“先按一次才能恢复”。

建议：按当前瞄准、最近有效动作、最近确认的有效轮盘来源逐项验证，改绑/清槽时清理过期目标；同时在快捷栏标出滚轮当前作用的槽。修复后覆盖动作改物品、改武技、清槽、读档和多个同类槽，保留旧释放事件失效规则。

证据：原生步骤32、34、37；关联`entities/player/components/player_input_controller.gd:290`。

## P2：第一次滚动只改变模式，没有改变实际形式

E为智能投射、最近元素为火时，实际形式是火石核心。第一次滚动后变成固定火石核心，实际形式和费用保持一致；第二次才变成树脂散射。智能项与相同实际形式的固定项相邻，造成一个额外滚轮步骤。

建议：将模式切换与形式切换清楚区分；世界滚轮优先切到不同实际形式，M/K继续提供明确的跟随/固定选择。显示此次改动，不自动略过缺料项并偷偷选择其他材料。

证据：步骤13→15→17，同一`charged_fireball`在前两步重复，随后才变成`cinder_volley`；关联`QuickslotMaterials.cycle`。

## P2：反馈重复，并混入另一个动作的预览

E投射缺少火石时，顶部通知正确显示投射拒绝；快捷栏上方又重复显示同一拒绝，前面还带着R的“火花→火球”预览，并与F交互条重叠。玩家同时看到两个动作名称，难以分清当前失败的是哪个动作。

## P2：需要法阵的形式隐藏了同样必需的材料余量

悬停树脂散射时，轮盘展示“20 MP · 脚下法阵充能 / 可释放”，没有显示所需树脂和口袋余量。该形式实际还消耗树脂，玩家难以在切换前比较资源。代码先生成口袋/背包数量，随后被法阵来源说明覆盖。

建议：同一处并列展示材料及口袋/背包余量、法阵条件和本次费用；智能项也显示解析后的实际需求，保持短而完整。背包有材料但口袋没有时，明确标为待整备。

证据：[轮盘画面](review/followup-ux/material-count-hidden.png)，步骤21；关联`gameplay/quickslots/quickslot_materials.gd:74`。

## P2：批量交易缺少总价、可买数量和具体失败原因

持有1币，选择单价2币的炭屑，将数量改为3。界面仍只显示单件2币与“购买所选数量”，没有显示总价6币、缺少5币或当前最多可买数量；操作按钮仍可点。点击后提示“货币不足，或对方没有空间接收付款”，把两种情况混在一起。

本次交易正确拒绝，玩家物资、零钱与商人炭屑都未变化，因此不是扣款/物品丢失问题。

建议：数量变化时更新总价、预计余款和具体阻塞条件；确认时仍重新校验实际库存与容量，避免只靠按钮状态保证交易正确。

证据：[数量3时的画面](review/followup-ux/batch-total-hidden.png)，步骤49与51；关联`gameplay/frontier/town_services.gd:95`。
