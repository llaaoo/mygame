2026-11-04，基于 [当前代码审查](./CODE_REVIEW_2026_11_04.md) 实施。按A—D批次完成行为修复、施法/状态边界、区域生命周期与维护性重构；法术组合规则、材料和区域数量保持现有MVP范围。

## 第一批已实现

### 存档文件与玩法恢复分离

`SaveRepository` 负责文件读取、格式校验、迁移、备份和替换；`SaveManager` 保留角色/世界/扩展区块的收集与恢复。

- 读取结果区分不存在、有效、备份恢复、无效、未来版本和I/O错误。
- 主档不可读时尝试有效备份；未来版本主档不回退为旧版本。
- 仅有效主档可以更新备份；恢复后的自动保存保留原有效备份。未来版本备份也不被覆盖。
- 临时文件、备份临时副本和最终替换分步执行，失败保留有效主档；无法恢复的原文件禁止自动覆盖。
- 注册的探索进度提供结构校验，避免错误类型被当作空进度。
- 手动读档失败不清除当前旅程；保存失败保留dirty状态并延迟重试。旧v1/v2迁移与当前v3格式兼容。

### 施法意图与费用规则统一

- 复用已有 `CastContext` 表达明确请求，由真实输入适配器采样一次Shift，写入 `Action.cast_context`。ActionResolver与执行读取同一个请求。
- 显式传入的 `empower=false` 不再被键盘状态改成true；无上下文的旧便捷调用保留输入适配行为。
- 新增 `SkillManager.can_start/use_source`，普通和自定义上下文调用共用一个执行实现，保留目标、世界与蓄力参数，失败统一退还法力。
- `CastCostPolicy` 共管普通动作和组合结果的法力、装备/熟练度冷却修正。
- 动作共享冷却与法术组合规则冷却继续并存；本次时长在提交时记录，UI不按变化后的环境推算分母。公共冷却修正参与准备计划重校验。

### 触发器与UI

- 简单触发器先匹配条件再占冷却；图模式通过叶节点接受动作后占一次冷却，条件门/空分支不占用。占用发生在动作回调前，避免重入。
- 触发冷却使用可暂停的模拟时间，过期移除记录，不再依赖系统时间。
- 一次性事件监听使用订阅标识，在调用前移除；嵌套发射也只调用一次。
- 技能栏在一次刷新内按基础技能与升级配置复用预览，冷却剩余/总时长共用查询。缓存只活一帧，提交仍重读真实条件。
- 七个槽位配置相同动作的复现从一次刷新22次预览降为1次；不同动作、不同升级仍分别计算。该结果是调用数验证，尚未作为目标硬件帧率结论。

## B—D批次已实现

### 类型化计划、事务与命中边界（B）

- `CastPlan / CastComponent / CastStatusRequirement`替代跨模块的施法计划字典；普通动作和条件动作共用规划、材料/恩赐修正与费用策略。`conditional_cast / field_type / preparation`声明能力，不再用ID白名单或后缀推断。
- `CastTransaction`协调法力、材料、状态与暂存效果；所有参与者完成状态变化后才通知。失败保留资源、原状态实例、层数/剩余时间/周期进度/版本和回复计时，不产生消费/施法事实。召唤注册、位移等副作用也延后至接受全部结果。
- `HitContext / HitResult`区分伤害和状态资格；默认无敌拒绝两者，可显式仅阻挡伤害。零伤害工具命中与共同动作family保留。ON_HIT在接受后、主伤害前处理反应；最终扣血由ON_DAMAGE或返回结果表达。
- `StatusInstance`持有定义、来源、层数、剩余时间和周期进度；移除原因区分自然到期、消费、驱散、替换、区域清理和恢复。
- `ActorAttributes`从永久基础值和临时贡献重算固定/百分比/速度倍率；成长、装备和Buff不会通过反向加减相互侵蚀。持久装备贡献保留，临时状态清除。
- HOT/DOT与持续AoE包含到期端点，只累计实际存活时间；表面迁移消耗超出时间。DOT保留原施法者、技能和施加时魔法强度，已施加DOT不受接触无敌吞跳，默认不再触发直接命中状态或命中熟练度。

### 公共区域生命周期、注册与索引（C）

- `SpellRuleIndex`在规则装载时按触发动作及状态/法阵作用域排序索引，保留稳定优先级。准备提交继续检查真实条件，不用UI缓存执行。
- `RegionSession`被探索、旧房间与场景地图共用。退出取消准备、瞄准、蓄力、引导、位移、召唤和临时状态，保留已排队的世界事实，再清理瞬态调度、推进scope/generation并卸载旧根。
- `CommandBus`入队与派发拒绝旧scope；旧遭遇回调校验generation。普通法术默认world为活动区域，随区域卸载；显式world仍由调用方管理。
- 各调度器拥有clear和查询API，外部不清空内部容器；表面显示与传播通过公开查询访问。
- `RuntimeRegistration`以弱引用暂存早于运行时就绪的注册，GameRuntime就绪时一次性处理。相同节点ID只注册一次，退出树自动注销；技能准备、法阵、蓄力/引导与状态共用模拟计时。

### 组件、内容、术语与工程入口（D）

- Player保留角色装配/属性/状态机接口；输入、施法过程、角色战斗事件与熟练度分别迁至`PlayerInputController / PlayerCastingController / PlayerCombatBindings`。删除无调用的旧PlayerAction与重复输入实现。
- MVPGame保留启动/切区/遭遇/死亡编排；进度命令与存档同步、界面呈现、区域装配迁至`ExplorationProgressService / ExplorationPresenter / ExplorationRegionBuilder`。机关仅发送solved/inspected信号。
- 引导脉冲也使用普通施法事务；先应用费用倍率再累计分数法力，大delta补齐脉冲，失败不扣材料并停止。释放其他槽不会消费当前蓄力。
- 区域的发现/遭遇/出口/世界事件/机关路线均为类型化Resource。`content/exploration/chapter.tres`统一登记9区域、10动作、15条法术组合规则和3委托。
- **法术组合规则**使用`SpellCombinationRule`，**制造配方**使用`CraftingRecipe`与`content/crafting/`。界面与文档不再用“配方”统称法术关系；旧存档`recipes`兼容读入`spell_rules`，新存档只写新键。制造发布一次完整库存变化，不改变法术知识。
- 内容验证器检查引用、重复ID、数值、材料奖励、机关非空/已知标签路线、交互净空与区域连通，错误包含资源路径；补充负例验证。
- 原五层测试继承迁至独立`tests/support/exploration_case.gd`，测试脚本互不继承；新边界检查复用简小的`mvp_fixture.gd`。
- GitHub Actions使用Godot 4.6.3与同一runner，冷导入、隔离执行、超时并上传日志；工作流未推送触发。
- ARCHITECTURE、RUNTIME_TOPOLOGY及战斗/世界/技能契约按公开同步请求、查询、提交事实和延迟作用域命令对齐。
