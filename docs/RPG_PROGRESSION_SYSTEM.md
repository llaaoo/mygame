# 等级、属性与角色 Perk

2026-11-10（上海）。参考《上古卷轴5》的“实践成长＋条件树”，复用本项目真实材料、装备和战斗承诺。这里实现可扩展的成长基座与首批节点，不宣称已完成长周期数值平衡。

## 成长与学习

`StatsComponent`独占角色等级、经验、主属性与属性点。角色每升一级获得3属性点；`SkillMasteryManager`按角色等级计算唯一Perk预算，每级1点。现有任务额外奖励属性点，仍不自动变成Perk点。角色与分支熟练度上限100；角色经验阈值沿用原曲线并增加数值边界。

熟练度由成功实践推进：合格武器命中/格挡每个family一次，成功制造、采集、首次发现、现场作业、强化和拆解走已提交事实。制造/采集/发现给4实践经验，其他上述事实给1；法术沿用实际成功施法、伤害、击杀的经验策略。每提升一级分支给25角色经验，多级累计。未命中、被拒绝/格挡伤害、周期伤害、失败、取消、回收、吃饭、休息、重复发现及无奖励试战不能借这条路径发放成长。真实再生后的再次采集仍可成长。

学习同时检查角色等级、该分支熟练度、基础属性、全部前置节点与剩余点数。装备或临时增益可帮助任务/作业/施法，但不能借来满足永久Perk的基础属性条件。一次确认只学习一个节点，拒绝不扣点，不会自动选择另一节点。成长不自动解锁未读的技能、配方或法阵知识。

## 属性实际联动

| 属性 | 当前作用 |
|---|---|
| 力量 | 近战加成每点2；负重承受相对10点每点增加2kg，影响实际负重速度和体力费用；有效属性参与现场/任务条件 |
| 智力 | 法力上限`30+3×智力`、魔法加成每点2；超过10后非休息作业每点缩短1%，最多20% |
| 敏捷 | 远射加成每点2，弓实际伤害用敏捷替换力量部分；移动加成每点3；原施法准备缩短规则保留；超过10后每点降低1%闪避体力费，最多25% |
| 耐力 | 生命基底`50+5×耐力`；体力上限`80+2×耐力`；体力回复`10+0.2×(耐力−10)`/秒（最低2），再结算补给/疲劳/装备/Perk；原需求、持续/环境/陷阱耐受规则保留 |

标准10点四属性仍为100 HP、60 MP、100体力、40kg负重承受。属性与Perk增加体力上限不补满当前体力，减少上限时只裁去超额。装备/增益通过同一有效属性投影，移除后重算。体力、负重在HUD、行囊、成长预览与执行查询中同源，不改变背包格数。

## 九条树与40个节点

保留毁灭、召唤、恢复、变化、幻术五条树的20个节点；修正其Resource脚本声明，旧文件此前部分节点未加载为`SkillPerkData`。删除代码中的重复默认树。原本无消费者或说明不符的节点改为已实现的伤害/费用/状态规则；两个无材料自动大法术节点改为降低元素施法费用，ID保留，不自动串招。

| 新分支 | 节点与实际用途 |
|---|---|
| 武器与武技 | 战斗调息：体力+15；连段节能：普攻/重击省12%体力；武技专注：武技省15%；反击研习：手动精准反击额外25%基础伤害；破势训练：武器冲击+15% |
| 防御与机动 | 稳健架势：格挡省12%；轻足：闪避省15%；守中回气：格挡时按正常回复20%回气，保留消耗后的延迟；长途步法：冲刺省20%；深厚储备：体力+20、回复+2/秒 |
| 制造与整修 | 工具熟习：非休息现场作业缩短15%；箭簇整备：标为弹药的配方产出+25%并向下取整；拆解辨材：真实装备拆解额外1碎料；整修熟手：强化省2币，仍付完整碎料；工序节律：非休息作业再缩短10% |
| 野外与补给 | 野外素养：需求损耗/疲劳积累降低15%；行囊经验：负重承受+10kg；识草：草药点多产1份，保留再生与空间约束；营地调息：每小时休息额外消除5疲劳；补给回气：有效食物增益期间额外回2体力/秒 |

新树每条5节点，先一个根节点再分两条路径，最低角色2级可选根节点；中段要求角色3级、分支3级和相关基础属性，末段要求角色5级、分支6级及更高属性。全部共用角色点数，因此同一阶段不能全部点满。法术分支继续要求其熟练度。

普攻与武技费用用同一物理请求重新检查；附魔、实物箭、法阵与材料仍全额消费。精准防御仍需手动提出反击，Perk不自动攻击。法术费用进入`CastCostPolicy`，状态时长进入原施加/保存路径；读档不重复乘时长。

制造预览与提交读取同一个产出查询，完整消耗原料；弹药产出最多提升50%，回收不加成，不制造无成本循环。强化与拆解仍指定UID，预览显示真实折扣/产出，失败回滚物资与经验。采集仍经过真实资源点、完整容量检查与再生时钟。加速作业不缩短睡眠准备、不加速世界小时；属性/装备/Perk在准备中改变会拒绝旧请求。Perk改变也进入CastPlan签名，不能以旧费用提交正在准备的法术。

## 操作与界面

灰河谷按 **P**，或从Tab顶部“角色成长”进入；训练师的属性入口打开同一页。分属性预览与分支树，树以有向连线表示前置，点节点看效果、条件和原因，再按“学习”确认。属性列表、分支、图和详情各自滚动；小窗口可横向查看树。世界、AI与资源时钟继续运行。升级只通知获得点数，不在战斗中强制打开面板。

旧房间验证模式的精通面板仍可手动进入属性分配，角色等级也读取同一StatsComponent。E与数字快捷槽、F交互、Ctrl武技与M材料轮盘保持原规则。

## 所有权、保存与接入

- `StatsComponent`：唯一角色等级/经验/主属性权威；`SkillMasteryManager`：各分支实践与已学节点，点数由等级、已花费与一次性历史信用计算。旧精通推导的`character_level`只作兼容投影，不再与角色等级叠加。
- `SkillTreeData / SkillPerkData`：只读Resource目录；可配置分支、坐标、等级、基础属性、前置和效果。目录拒绝重名、缺前置、环、非法条件、越界坐标、非有限数值、未知效果键及未承担费用的自动施法。新机制先接消费者再登记键；不添加另一套脚本语言。
- `ActorProgression`：无状态共同投影，组合有效属性与本角色Perk。`ActorActionController / StaminaComponent`继续拥有动作与资源；`InventoryService`通过组合根注入的只读Perk查询结算库存，UI不写状态。
- `CharacterProgressionScreen`只查询、提交训练/学习请求并请求保存。成功实践复用`GameplayFacts`，只在真实提交后奖励；同family防重沿用战役事实收据。

精通快照升级为schema2；旧角色等级、经验、属性点、知识、UID与物资保留。旧学派未花点与已花成本，和角色等级应得预算取较大者，一次性迁为历史信用；再次保存/读档不重发。重复ID、未知节点、缺前置、非法分支、超预算或非法数值会在加载前拒绝。旧主/备份恢复与新旅程归档流程沿用原实现。瞬时准备、连招与现场法阵不保存。

本次沿用Godot 4.6官方[场景组织与依赖注入建议](https://github.com/godotengine/godot-docs/blob/4.6/tutorials/best_practices/scene_organization.rst)：组合根提供依赖，定义与角色运行状态分开，UI不成为跨系统权威。验证结果见[RPG成长验证](RPG_PROGRESSION_VALIDATION.md)。
