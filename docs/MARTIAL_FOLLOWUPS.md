# 命中确认与接势武技

2026-11-09，Godot 4.6.3。接续[普攻连段](WEAPON_COMBOS.md)，把普攻、武技、附魔和对手准备状态组合成手动战术选择。本轮深化现有四个武技，没有新增知识ID、地图、配方或物资投放。

## 普攻接武技

指定普攻段对战斗角色造成未格挡的有效伤害后，在该段收招或原有接续窗口内按已绑定的武技键，会提出接势变式。每次仍需玩家按键；保留原完整收招和350毫秒单请求缓存，不取消当前挥击。可以继续左键完成普通连段，也可以改用武技结束连段。

| 武器 / 原武技 | 入口 | 接势形式与取舍 | 体力 / 冷却 |
|---|---|---|---|
| 刀剑 / 破势斩 | 第2段返刃有效命中 | 截势斩：起手0.28秒（常规0.46），距离62（66）、扇面65°（90°），前踏6（8）；保留2.1倍格挡压力，收招略长 | 26 / 共用原冷却 |
| 长矛 / 贯步刺 | 第2段递进刺有效命中 | 追身贯刺：起手0.24秒（0.38），距离132（145）、扇面22°（26°）、前踏20（28）；保留准备打断，适合近距离追压 | 25 / 共用原冷却 |
| 战杖 / 压阵横扫 | 第2段杖尾顶有效命中 | 回旋压阵：起手0.36秒（0.55），扇面210°（175°），距离84（92）、推移48（64）；更快覆盖侧后，牺牲伸展和推远能力 | 30 / 共用原冷却 |
| 弓 / 蓄力穿射 | 第1箭稳弦射有效命中 | 追隙穿射：拉弦0.52秒（0.85），距离580（680）、倍率1.5（1.8）；保留准备打断，再消费一支真实箭 | 24 + 1箭 / 共用原冷却 |

括号内为常规形式，费用为定义原值，仍受原负重与熟练度规则修正。接势不是免费强化：通过命中和时间条件换取更快的起手，保留范围、伤害或推移的取舍。没有额外MP消耗、自动出招、免费弹药、缩短已有收招或重置冷却。

例如把贯步刺放E：两次手动左键，第二刺有效命中后，HUD显示“可接 E · 追身贯刺”；再手动按E。若敌人即将离开近距离，可按Ctrl+E固定常规贯步刺，使用其更远的前踏与距离。其他快捷键与E完全同样处理，E与1仍是独立槽。

## 操作、来源与反馈

- 默认按武技键读取当时的接势条件；**Ctrl+武技键固定常规形式**。Shift继续显式请求释放当前真实武器的整层附魔，可与Ctrl组合。左右键仍只负责攻击与格挡。
- 输入时复制形式和原普攻动作family；执行时重验该机会、武器UID、快捷绑定、知识、冷却、体力、箭矢及显式附魔来源。若已选接势失效，会拒绝而不是改成常规。此前已选常规的输入，也不会被后来到达的箭偷偷升级。
- 仅接受共同命中链中对战斗角色造成的真实未格挡正伤害。挥空、打墙、无敌拒绝、格挡削血及破坏普通场景物件不确认接势。持续伤害和元素波不会创建新的普攻机会。
- 远程箭可在普攻收招完成后、原窗口尚在时确认对应动作；只认同一family。推进下一段、用武技、开界面、格挡、闪避、失衡、换装、死亡、离区及读档后的旧箭都不能恢复机会。机会不叠层、不保存、不写入物品。
- 接势与常规形式共用一个武技知识、快捷绑定和冷却。已学会旧武技的存档可直接使用新接势规则，无需重学或重新开始。未学会时仍需现有训练师或技能书。
- HUD在真实可用时显示已编组的武技键与变式名；快捷栏标记“接势”，悬停、K详情展示规则与取舍。Ctrl按住时预览也切回常规；体力和箭矢不足按实际状态灰显，等待输入本身不消费费用。
- 普通附魔仍逐击施加额外伤害和异常积累；Shift接势武技仍在实际挥出/离弦时提交涂层与箭矢，不在入缓存时消费。元素波沿用原武技释放形态和同一命中family防重。

## 对手与内容配置

AI只在可见目标和已学知识下选择：确认命中后的接势、针对格挡的破势、针对准备的刺击/穿射，或体力下降时的推扫。先检查实际费用、冷却、弹药和射界，再提交同一Action。接势可替代原闲置停顿，但不会跳过正在进行的动作恢复；低体力仍优先撤退，没有自动补材料或释放附魔。

ActorCharacterData新增`techniques`，声明角色首次生成时已掌握的武技。当前只为既有的失联队长奥伦配置破势斩，作为实际世界接入样本；装备、属性、敌人数及掉落预算不变。已有角色存档里的知识和冷却继续作为权威，包括显式空记录；不会用新模板覆盖。其他NPC未配置的武技不会凭空获得。

## 架构与扩展

沿用Godot的[Resource定义与RefCounted运行值](https://docs.godotengine.org/en/4.6/tutorials/best_practices/node_alternatives.html)和项目既有职责：

- `MartialTechnique.followup_after / followup_profile`描述允许衔接的普攻下标及动作定义，可选配置，不额外登记一套技能ID。配置校验重复/负下标、缺少配对定义、非法动作与弓/近战投送不匹配。
- 每角色`WeaponComboState`保留本次普攻family及有效接触事实；接受新段和所有原取消路径清理。没有独立的连势能量条、Buff框架或第二个执行器。
- `ActorActionController.technique_view`供输入、AI和UI查询同一形式与实际费用；`capture_technique_intent`将查询结果变为短期意图快照。未调用捕获的旧领域请求保持常规形式兼容语义。
- 近战和WeaponArrow从统一HitResult确认接触。箭回调检查动作节点有效性并比对family；不改CombatExecutor的伤害、事件顺序和资格规则。
- 接受、体力、冷却与真实挥出/离弦事务继续走原物理执行链。只读定义不保存角色进度，知识/冷却沿原持久化保存，存档协议不变。

## 验证与覆盖限制

`martial_followups`覆盖四类真实接触、收招缓存、费用与共用冷却、挥空/格挡、明确常规选择、过期/改绑/缺体力/换装、晚到箭与旧箭、实际第二箭、210°侧后命中及48距离碰撞推移、真实附魔释放、AI正常choose链和初始/已保存NPC知识。该领域测试隔离AI与部分计时，用目标生命重置区分边界，不作为平衡验收。

`martial_followup_input`通过实际Godot键鼠事件完成四套“普攻命中 → E接势”，验证共享预览/HUD、自然体力和冷却恢复、Ctrl+E、真实两支箭及F5/F9瞬态清理。世界与其他敌人保持正常模拟；装备、知识和测试位置由fixture提供，一个目标停用决策与移动以隔离输入，不能据此声称击败正常AI或完成自然开荒。
