# 灰河谷 HUD 与界面重构设计 v1

状态：**设计提案与交互原型，尚未迁移到 Godot 正式界面。** 本轮不改变战斗、库存、存档或操作绑定。

[交互原型与运行方式](design/ui-system/README.md) · [原型入口](design/ui-system/index.html) · [现行操作](CONTROL_SCHEME.md) · [世界观](WORLDVIEW.md)

## 1. 设计目标

把界面从“把系统能力摆出来”转为“帮助玩家完成当前意图”。高标准体现在战斗可读、来源可信、交互一致和长期扩充的成本，不以装饰密度衡量。现有俯视像素场景仍是视觉主体；不通过铺满大面板来制造所谓大作感，也不承诺仅靠换 UI 达到 AAA 整体制作水平。

三条视觉支柱：

- **边境实用品**：墨绿、炭灰、旧黄铜、布纸质感。直线与短切角，轻装饰；主按钮靠层级和留白识别。
- **克制的异质力量**：元素颜色仅标识具体涂层、阵能与来源。普通人的界面不铺设蓝色法力装饰；神明与魔法不混为同一图形语言。
- **让世界留在画面里**：探索 HUD 低密度，战斗只增加当下目标与短窗口；完整管理页使用统一稳定底色，不在战场中央滚动大段系统说明。

参考原则：Skyrim 的共同世界与人物装备、Outward 的真实准备和资源取舍、成熟动作 RPG 的输入响应与短反馈。参考交互原则，不复制其美术、版式或受保护资产。

## 2. 当前审查与改造边界

| 当前承载 | 问题与代价 | 处理方向 |
|---|---|---|
| `ui/hud.gd`、`ui/skill_bar.gd`、`gameplay/frontier/frontier_hud.gd` | 同屏信息来源分散，战斗、任务和操作说明竞争注意力 | 一个 HUD 编排入口，保留各领域查询；显示预算统一管理 |
| `ui/actor_inventory_screen.gd` | 已有统一行囊基础，但装备、来源、长详情和动作关系仍较密集 | 延续原入口与服务，重排为纸娃娃、物品、详情三栏 |
| `ui/material_wheel.gd` 与技能整备 | 完整知识目录和临场可用形式容易混淆 | K 管配置，G 管当前可以执行的形式 |
| `FrontierHub`、交谈、成长、现场作业页 | 导航与布局习惯不统一，常要重新寻找返回和执行按钮 | 同一菜单壳；现场行为使用小型抽屉 |
| `GameUIStyle`、`ExpeditionNavigation` | 已存在共享主题和导航边界 | 扩展现有基础，避免再造第二套主题、路由或全局总线 |

这是展示层重构。物品、快捷槽、施法、人物关系、成长、任务和时间的领域权威不转移到 UI。现有服务的规则错误不能通过“按钮看起来可用”掩盖。

## 3. 信息架构与入口

| 层级 | 内容 | 输入与退出 |
|---|---|---|
| 世界 HUD | 资源、13 个独立快捷槽、一个追踪目标、方向、短交互 | 持续游玩；没有覆盖所有操作的常驻说明墙 |
| 战斗轻层 | 当前槽形式、目标摘要、连招武技窗口、动作拒绝 | G/中键选择；Esc 先关轻层；仍可移动、防御、闪避 |
| 现场抽屉 | 阅读、搜取、现场作业、短交互目标选择 | F 进入；显示来源、距离和风险；Esc 回世界 |
| 统一整备壳 | 行囊、角色、技艺、手札、行路图 | I/O/N、P、K、J、M；固定返回位置 |
| 人物/地点工作页 | 交谈、交易、课程、工作台、休息 | 从人物与物体进入；沿用整备壳的字体、详情、风险栏 |
| 系统层 | 存读档、设置、重新开始 | Esc；确认框仅用于确实有不可逆后果的行为 |

I/O/N 是同一行囊的不同焦点；O 聚焦穿戴，N 聚焦补给，不产生独立装备或消耗品背包。Tab 回上次管理页；界面快捷键与按钮提示最终都读 `InputBindings`，设计稿上的字母不是新的硬编码权威。

## 4. 探索与战斗 HUD

基准 1920×1080，逻辑安全边距 32–48px；1440×900 正常工作；960×720 使用紧凑布局。不要整体缩放世界来容纳 HUD。

- 顶部中央：窄罗盘与亲历地点，只有当前追踪目标、个人路标、已知地点类别。危险不能通过罗盘直接透墙定位。
- 右上：一个目标，最多两行正文。完整步骤在手札。战斗时压缩为短标题，不滚入新教程。
- 左下：生命、体力，觉醒后再出现法力。资源条保持位置，危急值附数字/符号，不能只有红绿差异。饥渴/疲劳等非战斗资源平时收为状态，接近阈值时展开。
- 人物 Buff：状态符号与叠层，悬停/焦点显示来源、影响和剩余时间。负面状态与正面状态分组，最多展示高优先项与“+N”，不无限挤占画面。
- **武器涂层独立一行**：武器标识、元素、剩余时长/充能；换武器立即读对应实例，不能把它当成跟随人物的 Buff。
- 底部中央：唯一的 13 槽快捷栏，Q/E/R 与 1–0 各自独立，可放动作或物品。视觉分组帮助定位，不限制槽类型。显示关键余量、明确锁定、冷却与不可用原因；同名喷剂分清具体瓶。
- 中央留白：只有瞄准/交互与当前战斗反馈。F 提示一次只对应一个实际目标；重叠目标提供小列表，不自动误选价值最高的对象。
- 当前敌人：一个聚焦生命/稳定摘要与关键状态；其他敌人只在受击/威胁时显示简条，避免遍地血条和数值。
- 武技机会：靠近快捷栏显示“轻→重 / 招名 / Ctrl+左键 / 窗口衰减”。不能为了易读延长领域窗口；Ctrl 换招不刷新截止时间。附魔强化另外显示显式 Ctrl+Shift 意图与消费。

反馈顺序：动作是否被接受 → 打中/格挡/失衡等结果 → 资源变化。失败显示一条可执行原因，例如“指定喷剂已空”，不连刷全部规则。普通战利品合并短通知，关键发现有单独记录入口；拾取播报不能盖住攻击预警。

## 5. 统一行囊与装备

三栏：左边实际穿戴与关键派生值，中间实物列表，右边所选物的详情与动作。顶部导航、返回、底部生命和危险状态固定；列表和详情独立滚动。

纸娃娃正式版复用角色的真实装备与外观目录，放大预览不创造装备。点击槽位筛选适配实物，空槽明确；换装后即时显示真实穿戴与属性变化。不要用泛用人体模型假装已有精细角色资产。

中栏有两组正交筛选：来源（全部/口袋/背包/附近明确容器）和类别。默认“全部”是聚合视图，不是可跨距离使用任何东西的万能口袋。搜索、排序和切页不重置选中 UID、剂量或涂层；列表可切为图标网格/紧凑条目，图标不靠颜色区分品类。

右栏依次是名称与来源、核心作用、当前实例状态、少量比较值、主要动作、展开细节。背景故事默认一段，完整规则展开。显示“出售预览”与“参考价值”时明确不同，不能把基础价值当成任何商人的报价。

| 意图 | 默认操作 | 反馈与保护 |
|---|---|---|
| 看/比较 | 单击，Shift 对比同槽 | 同一件显示“当前穿戴”，没有可比项则说明 |
| 使用/穿戴 | 双击或详情主按钮 | 交给真实服务，失败不改显示中的库存 |
| 快捷绑定 | 右键/详情“放入快捷槽”→点目标槽 | 两步完成；保留实例 UID，E 与 1 不互相修改 |
| 转移 | 来源间拖放，另有按钮 | 预览容量与数量，失败物品仍在原处 |
| 丢弃 | 右键→数量；单件可直接确认 | 真实落地容器；已穿戴/关键物另验规则；不静默删除 |
| 整理/拆分 | 低频菜单 | 保持剂量、所有权、涂层，不能自动合并不同状态瓶 |

关闭后保留筛选、选中、滚动位置；换档/换角色清掉旧 UID。拖动不是唯一入口，鼠标菜单与键盘可完成同样请求。

## 6. 临场选材与完整技艺页

K 页面分“基础操作”“武器连招”“已学知识”，同一位置展示实际条件、当前源策略与槽位。不可施放的知识仍可查阅并标明觉醒/工具/材料等原因。武技在这里配置每个组合最多两招，不允许再放入快捷槽。

G/按中键打开当前槽的轻量选择层；世界滚轮在可用形式间切换。1–3 项用紧凑扇面/横列，4–8 项用轮盘，多于 8 项先按基础操作分组，不能创建绕过领域规则的组合宏。

- 只读 `CastPlan` 当前可用形式；普通形式与材料增强都满足时并列。
- 扇区用形式/来源身份稳定定位；打开后失效的项变成不可确认并说明原因，不能把另一个选项塞进已悬停扇区。
- 选择只改准备，不释放、不扣费。确认与实际释放分别重新验证；移动或危险导致条件变化要明确反馈。
- 智能跟随只根据最近**成功**的元素调整候选偏好。当前形式、固定/跟随标记、下一次真实总费用同时可见；没有任何静默换瓶、补阵或缺料降级。
- 指定瓶耗尽仍保留原身份，清楚提示去换源。未觉醒者主动法术锁定，普通喷剂、附魔抹布不因此一起锁死。
- 控件移动不改变防御朝向；鼠标释放事件由选择层消费，关轮盘后不能发出额外攻击或对新来源补发旧按键。

目标操作：已编组的动作从战斗到换形式只开一个轻层；从物品详情绑定槽位只需两步；查看知识不必穿过选材轮盘。

## 7. 其他系统的统一操作设计

| 页面 | 主要布局与系统联动 | 本轮原型覆盖 |
|---|---|---|
| 角色/Perk | 左分支，中属性与实际派生值，右/下节点详情；预览效果、费用、前置后确认 | 属性、一个可购买节点、条件示意 |
| 手札 | 左分组任务/人情/发现，右当前步骤与获得线索；一键追踪/地图 | 首次出征记录、追踪切换 |
| 行路图 | 亲历地图为主体，地点卡不遮路线；未知区只显示已有知识 | 结构示意地图、地点卡、缩放/平移；非真实坐标 |
| 对话 | 人物与态度，短段话题和明确服务入口；交易/授课先报总费用 | 话题切换与课程报价；不执行真实教学 |
| 交易 | 玩家与商人双库存，中交易明细；买/卖切换明确，底部真实零钱与容量 | 详细交互设计见下；未做独立原型 |
| 制造/整修 | 配方列表，需求来源与产出详情；保留配方选择，结果不强制跳页 | 两份样例配方加工，扣原料/增产物 |
| 搜取/容器 | 紧凑来源双栏，单件/选取转移；装备和专业部位分开 | 仅阅读入口提示；未做实物转移原型 |
| 现场作业 | 实际部位、工具、知识、风险/耗时与可中断进度 | 未做可操作页；复用小抽屉规范 |
| 休息 | 选择小时、开始/结束时刻，食水与危险预估；准备可取消 | 未做可操作页，禁止“3秒=一夜”文案 |
| 存档/系统 | 旅程列表含地点、游戏时间、现实日期、版本兼容；重开单独确认 | 设置、危险演示、重开确认；不读写真实存档 |
| 阵亡/重返 | 明确实际损失、掉落地点与可恢复资源；继续/读档不混淆 | 未做可操作页，沿用系统壳 |

交易操作：默认单击查看，双击/明确“卖出”提交；批量用显式待售清单，显示每件 UID、数量、涂层、报价与买家资金，结算前重新核验。已装备/快捷来源给出解释，不自动代卖其他同名物。稀有任务物的限制来自领域规则，不由 UI 自行加锁。不能用“商店”入口把出售再藏进背包多级菜单。

课程操作：话题→课程列表→条件和费用→确认。普通武技标明组合与体力，不使用法术式 MP 锁；已学不重复收费，课程结束后给一个“查看配置”入口，不自动替换当前武技。

## 8. 实时世界与输入契约

所有整备、地图、对话和系统页不暂停、不减速。固定时刻栏只是提醒，实际安全性来自位置与敌情。完整页接管攻击/施法输入，轻量轮盘保留明确约定的防御动作；危险后显示高对比短警报，Esc 一步回世界。UI 不替玩家自动闪避、退敌或延长 Buff。

输入所有权按顶层实际控件处理：确认框 → 选材/右键菜单 → 当前管理页 → 世界。Esc 先关最上层；同一帧关闭事件不能继续传给下一层。搜索框中按字母不得打开其他面板。导航键不触发世界技能；失焦、区域切换和读档清理拖拽/按住/悬停上下文。

工具提示需鼠标停留约 250ms 后出现，离开即收；关键失败、费用和交互不能只藏在 hover。布局动效 120–180ms，关闭立即归还输入；武技倒计时、受击信号按真实事实驱动，不播放伪造循环机会。

## 9. 视觉与可访问性规范

| Token | 方向 |
|---|---|
| 底色 | 深墨绿 `#101716`，面板 `#19211f`，仅少量可控透明 |
| 正文/次级 | 米灰 `#e6e1d2` / 灰绿 `#9aa59b`；暗底正文目标对比至少 4.5:1 |
| 交互重点 | 旧黄铜 `#c7af77`；不是所有标题都涂金 |
| 生命/体力/法力 | 赭红 `#b96556` / 灰橄榄 `#a5ae82` / 灰蓝 `#82a5ac`，另加图形和标签 |
| 间距 | 4px 基数，主要组距 16/24/32；分隔线优于层层描框 |
| 字体 | 沿用项目 Noto Sans SC；基准正文 16px，关键数据 16–20，次级 12–14，标题 24–32 |
| 输入目标 | 常用点击区目标至少 40×40；小型指示不充当唯一按钮 |
| 偏好 | 字号 100/112/125%，增强对比，减少动态；偏好不进旅程快照 |

大字时让列表/详情重新排版和滚动，不裁文字。960 宽行囊左栏可折叠为穿戴摘要，详情保持可见；窄屏不把全部字号压到 9px。手柄导航本轮不做，但焦点顺序、焦点框与无 hover 的信息入口保留，避免未来推倒重做。

正式迁移还需核验所有状态的对比、遮挡与素材质量；原型中的静态生命值、涂层秒数和示意 Perk 数值不构成最终平衡设计。

## 10. Godot 落地结构

沿用 `GameUIStyle`、全局 Theme、`ExpeditionNavigation`、既有页面和现有输入适配器。首先整合显示与生命周期，避免直接重写全部系统。

建议职责：

- HUD 编排器组合资源、目标、快捷栏、状态与通知，不拥有这些领域的可变状态；有限状态投影只在事实/显示条件变化时更新。
- 现有导航扩展为统一的页面和轻层输入 scope，持有返回栈、焦点与临时视图状态；不创建持久化全局 UI 单例来引用区域角色。
- 共用菜单壳负责标题、导航、底栏、返回与危险提示。物品条目、状态图标、费用条和详情分隔等用小场景复用；不把每一条文本都做成抽象框架。
- 页面 Presenter 向 `InventoryService`、`QuickslotLoadout`、`CastPlan`、`ActorProgression`、NPC/任务服务请求只读投影并提交原请求。接受/拒绝由原执行器返回，已提交事实才产生成功动效。
- `ViewContext` 仅存筛选、焦点 UID、滚动位置、来源选择与返回入口。物品数、剂量、Perk、学习结果、时间仍由原所有者维护；不得让 UI 的示例数据结构变成存档格式。
- 刷新不重建正在按住/拖拽的控件，不抹键盘焦点。订阅有退出清理；区域 generation、UID 和服务范围在确认时重验。旧页面不通过闭包长期抓住已离区角色。

纸娃娃读同一装备外观目录，状态图标读同一状态定义，材料可用性读同一规划。不要写“UI 版配方”“UI 版施法条件”“UI 版报价”来修复显示不一致。

## 11. 分批实施与验收

| 批次 | 可交付范围 | 必须通过的验收 |
|---|---|---|
| A：统一底座 | Theme token、菜单壳、导航/输入范围、资源 HUD 与通知 | 实时 AI/受击不中断；Esc 无输入泄漏；未觉醒无 MP 假入口；Q/E/R+1–0 全独立 |
| B：行囊 | 纸娃娃、来源筛选、详情比较、快捷绑定、丢弃/转移 | 实际 UID/剂量/涂层守恒；容量失败不丢物；鼠标与键盘均能完成 |
| C：战斗整备 | G 形式、K 知识/编组、武技窗口、涂层展示 | 失效项不替身；选择不消费；普通喷剂与主动法术资格区分；真实窗口无伪造延长 |
| D：人物与现场 | 交易/授课/制造/搜取/作业/休息 | 真实双方库存、资金、时间、范围；失败回滚；正常敌情可打断 |
