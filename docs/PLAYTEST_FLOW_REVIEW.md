# 灰河谷系统衔接与操作试玩

后续处理见[操作闭环与智能施法](PLAYER_FLOW_AND_SPELL_ASSIST.md)。下文保留基线版本的原始发现，不将后续修复改写成当时已通过。

2026-11-08。基线 `aeae24de61b264187698425342d8ebbb15563baf`（main，PR #24 后）。本轮只记录试玩和改进方向，没有修改玩法、规则、按键或数值。新发现不代表已修复。

结论：制造、真实口袋、组合施法、战利品交易和训练能够组成实际循环，但玩家很难判断“东西已经有了”和“现在能用”之间的差别。优先解决准备状态和操作结果的反馈，再缩短重复交易、查阅记录的路径；暂不增加新系统或材料种类。

## 方法与实际路线

云端 Linux、Godot 4.6.3、原生 X11 窗口、OpenGL Compatibility、Mesa llvmpipe，主窗口1152×648，另实际缩至960×540。使用独立XDG目录和存档3，正常AI、原始100 HP / 60 MP；没有传送、发放物资、直接改时间、关闭敌人或修改领域状态。

主流程由 `tools/first30_probe.gd` 的实际按键与指针事件驱动；临时扩展只查询界面/库存/排产及截图。输入辅助知道作者点位，不是盲玩。最后的购买武技、绑定E、小窗口查看和保存使用XTest系统键鼠事件，再由新Godot进程读取同一游戏存档核对。共享桌面控制工具未提供，本轮未验证实体键鼠手感、声音、Windows、硬件性能或控制器。

实际路线：读镇中手册→领补给→出售3份树液、购买金属碎料→给店家排产木杆箭→工作台制6支箭与1颗火石→休息1小时、检查排产→北路读猎营记录→选火石阵但无法布阵→检查背包、撤至更远处整理口袋→返回亲手布阵和施放火花→击败守备兵、拾取实际战利品→返镇换上驿路短刀、出售护具→夜访训练师→休息6小时后白天学习破势斩、绑定E→小窗口查看行囊→保存并重新启动核对。

全程菜单时间和诊断等待都推进世界，不能用游戏日期或总墙钟推算新人通关耗时。本轮也没有同检查点基础打法对照，不作平衡结论。

## 已复现问题

### P1：制造完成没有接上战斗就绪，失败时反馈不足

自然操作后口袋已占12/12格，背包只有2/30格、总重9.4/40 kg。新制火石 `item.94` 进入背包，口袋中为0。玩家在猎营选了火石阵，轮盘显示灰项但可以保存该选择；随后重复按5，没有法阵、没有扣法力，也没有明显的全局拒绝原因。

打开行囊转移火石才看到“附近有敌人，先脱离战斗再换装。”此时守备兵距离491.32、发现距离440，仍为Idle：可以安全读记录，却不能就地整理材料。实际限制来自500范围的附近敌人检查；这也不是玩家正在进行的“换装”。玩家很容易误判技能坏了或材料没有做成功。

实际退至更西侧，先把零钱放入背包、再把火石放进口袋，返回同一地点后组合立即成功。没有改库存、敌人或技能选择。消耗1颗火石，布阵费用8 MP、两次火花各12 MP，生成两颗火球；目标被击败，受伤0，结束MP29（包含过程中的自然恢复），输入辅助战斗段约4.31秒。这证明组合链可运行，主要断点是准备条件的可见性，不据此调整平衡。

建议：制造结果显示实际产出容器和“口袋可用/背包待整备”；轮盘与快捷槽同时显示当前来源及可用数量；拒绝施法时明确提示“火石在背包，口袋0”，可导航到对应物品。整理失败说明具体原因与可行下一步，避免把附近闲置敌人称为已经交战。继续保留实物来源、亲手选材和布阵，不自动补阵或偷偷换源。

证据：步骤43、73—89、91；[原始摘录](validation/playtest_flow_review.json)。[行囊中的拒绝提示](review/playtest-flow/preparation-blocked.png)。关联实现：`InventoryActions.transfer`、`ExpeditionEquipment.change_reason`、`CampaignSession.has_hostiles_near`。

### P1：箭的制造详情使用配方ID，产出和持有量显示错误

工作台显示 `arrows` 和“加工：arrows”，而不是木杆箭。一次制造实际增加 `arrow ×6`，界面仍显示“产出 ×6 · 持有0”，且缺少产出物描述和明确成功反馈。玩家必须打开背包才能确认刚才究竟做出了什么。

建议：配方ID与产出物ID分开使用；标题、图标、持有量和说明读取真实产出定义，制造后给出数量、容器和失败原因。这里无需改变配方费用。

证据：步骤39—41，[制造后的画面](review/playtest-flow/arrow-after.png)。`CastingWorkshop._craft_rows / _craft_detail` 使用配方ID查物品，而真实产出是另一个ID。

### P2：连续交易每次都要重新选物品

从树液9份连续卖出3份，每卖1份右侧详情与出售按钮就清空。下一件必须回到左侧重新选。3份需要6次有效点击；在原出售按钮位置再点一次没有作用。没有数量出售入口。

建议：刷新后保留被选UID和焦点，数量耗尽再移动到下一行；提供显式数量/整叠交易，沿用库存事务、支付与容量校验。避免把日常补给变成反复找同一行。

证据：步骤18—27，树液9→6、玩家零钱0→3、商人零钱160→157。[选中物品](review/playtest-flow/sale-selected.png)、[卖出后详情消失](review/playtest-flow/sale-cleared.png)。关联实现：`TownServices._request / _rows`。

### P2：手册的J提示与打开后的内容不一致

读手册时已经正确自动学会知识，Esc关闭不会丢失。问题是提示说可以按J回看，J却先进入“委托与旅程”，默认选中“不再守候的命令”，并非刚读过的手册；需要再进“知识”、再找手册条目。知识页默认的旅程总览还同时铺出大量委托和系统说明。新档委托列表展示11项进行中的条目，当前相关信息不突出。

建议：J保留上次页签/条目，或优先定位最近阅读、当前追踪的信息；给记录提供直接返回入口。已知信息分层展示，不靠更多长文本解释菜单。此处是定位和信息层级问题，不是知识没有保存。

证据：步骤5—10，[J打开后的默认页](review/playtest-flow/journal-default.png)。关联实现：`FrontierHub.open` 的选择/页签初始化。

### P2：排产确实完成，但离店后缺少完成提示

第一批木杆箭排产后离开，返回时商人箭24→30、队列为空，没有外部完成反馈。再排一批，离店并在篝火实际休息1小时后，商人箭30→36、队列再次清空；HUD通知只有休息结果，没有店家完工/可购买提示。

建议：排产接受和完成分别有简短反馈，在旅程或商人标记里留一条可回看的记录，说明“店家完成，可购买”。这些货属于商人，不应改成玩家免费领取，也不应自动转入玩家库存。

证据：步骤33—34、50—58；原始摘录同时保留队列和商人物资。排产、时间推进和商人物资联动本身已经生效。

### P2：夜间服务拒绝给出互斥原因，缺少等待方向

第1天22:41到训练师白天工作点，那里没有服务；继续找到休息中的训练师，F提示“当前无法提供服务：未当值、已死亡或关系敌对。”没有说明实际是未当值，也没有显示当值时段。对仍站在眼前的NPC，这条文案尤其容易误导。

实际休息6小时后，第2天10:31回到工作点能正常打开训练。随后购买破势斩、到K武技页选择并点E槽成功，说明服务与学习链正常；主要不便是玩家缺少何时/去哪里继续的提示，以及学习后仍需退出服务再找编组页。

建议：返回单一实际拒绝原因，显示已知工作时段和地点；购买成功提供“打开快捷栏编组”入口，仍由玩家选择槽位，不自动绑定或替换现有内容。

证据：步骤110、114、120—126；[夜间拒绝](review/playtest-flow/night-service.png)、[手动绑定后](review/playtest-flow/technique-bound.png)。

## 确认可用与覆盖边界

- 核心组合能结算，实际材料按来源消耗，击败后的装备可以拾取、穿戴和出售；零钱又可用于训练。没有观察到此路线复制战利品或凭空补货。
- 休息1小时与6小时均是实际作业输入，成功才消耗相应补给，并推进游戏日期、需要值、商人排产和NPC当值。本轮不是“休息只有几秒没有时间联动”。
- 手册知识自动记录；K中可手动选择破势斩、点独立E槽完成绑定。保存后新进程读回 `blade_breaker=true`、E绑定、短刀UID `item.30`、零钱1；这不是所有存档迁移路径的全面验收。
- 960×540实际打开行囊、选择箭的详情、按Esc回到世界均成功，详情拥有滚动容器；没有完成每种窗口/菜单/焦点组合的遍历，也未做鼠标滚轮全覆盖。[小窗口详情](review/playtest-flow/small-inventory.png)。
- 中途有一次驱动步行目标容差过严（角色已到目标约28单位，阈值24）导致超时，不作为导航缺陷；一次训练点击发生在夜间服务不存在时，不作为课程丢失。
- 第127条命令误用 `text` 而非驱动要求的 `label`，导致测试脚本异常、命令轮询中断。游戏仍继续运行，后续改用XTest输入完成上述学习和小窗口检查；原进程保存后由测试方终止。不能宣称该进程无脚本错误或正常退出。重新读档进程退出0，仅有软件显示驱动不支持切换VSync的警告。此异常属于测试输入格式错误，不列为游戏缺陷。
- 未覆盖全部武器手感、远程瞄准、喷洒按住/松开、死亡回收、所有制作/升级/拆解分支、长流程副本和同档打法对照。本轮没有运行完整自动回归，也没有将旧版本测试数当成本轮成绩。
