# HUD / UI 设计复审与 v1.1 修订依据

评审日期：2026-11-12。对象是 [v1 设计与 HTML 概念原型](UI_SYSTEM_DESIGN.md)，不是正式 Godot UI 的新一轮试玩。基线提交 `2303650`，合并提交 `b1c87af`。复审当轮只更新设计、审查记录与复现工具；原始发现与证据保留。后续原型优化状态见第9节，正式游戏界面仍未迁移。

## 结论与保留项

方向值得保留，但目前适合作为结构与风格探索，尚不足以直接作为正式界面的实施定稿。最大问题依次是：输入和状态反馈不闭合、实时战斗与大面板冲突、物品辨识和高频操作不够直接。继续堆装饰或把十个页面逐个搬进 Godot，会把这些问题固化。

应保留：一个快捷槽权威、E 与 1 独立；实际来源与余量；G 的可执行形式和 K 的完整知识分工；武技独立于快捷栏；统一行囊与纸娃娃；墨绿/炭灰/旧黄铜基调；世界持续运行。顶部十个演示按钮属于评审工具，不计为游戏内导航问题。

P0 表示正式迁移前必须解决的交互或状态错误，P1 表示首批迁移必须达到的可用性，P2 表示后续视觉与扩展质量。优先级不意味着原型缺陷已存在于正式 Godot 实现。

## 1. 直接复现的交互问题

| 优先级 | 证据与触发 | 玩家代价 | v1.1 决定 |
|---|---|---|---|
| P0 | `keyboard-focus`：I 后按 Tab，管理页关闭 | 无法正常用 Tab 遍历焦点；与 Tab 回上次页的世界操作冲突 | 世界 Tab 打开上次页，页面内 Tab/Shift+Tab 只移动焦点；Esc 管返回 |
| P0 | `double-click-equip`：真实双击短弓，主手仍是短刀 | 提示承诺与实际操作不一致 | 保留控件身份；单击只改选中，不整页重建；双击或主按钮走同一请求 |
| P0 | `confirmation-input-scope`：重开确认框存在时仍能点击后方动态设置 | 顶层确认不真正独占输入，正式版可能误执行底层操作 | 确认框拦截指针/键盘，焦点限制在当前范围；关闭事件不向下透传 |
| P0 | `all-slots-source-access`：给 1 绑定铭刻并选择该槽后，G 回到 R/火花 | 13 个可放动作的槽在来源操作上不平等 | 使用同一当前槽投影；G 不把数字槽改成 Q/E/R，不靠硬编码键组判定能力 |
| P0 | `current-form-feedback`：选火石阵后重开选择层，没有当前项标记 | 无法确认下一次到底使用哪种来源；资源消费不可预测 | HUD/轻层明确显示当前形式、来源、总费用与固定/跟随；失效保留身份并解释 |

| P1 | `equipment-slot-filter`：点击无头部装备的头槽，仍列出 5 件装备，详情显示短刀 | 空槽没有说明，容易认为短刀可以穿在头部 | 类型+部位筛选，空状态“没有可穿戴头部装备”；不能回选不相关的物品 |

## 2. 视觉表现：配色可保留，辨识与风格连接要重做

### 2.1 世界、物品与人物需要同一种制作语言（P1）

目前世界是低分辨率像素图，物品是细线 SVG，纸娃娃是平滑几何人体。它们适合低成本示意，但不能直接充当最终美术。尤其纸娃娃放大后，角色并没有更丰富的穿戴表现，只是示意图占了更多空间。

正式方向：物品使用与世界同源的有实体轮廓的小图，短刀/弓/盾在小尺寸就能分辨；同类材料用形状与容器标记区分，不全部复用岩石/瓶子线框。纸娃娃复用实际装备外观，像素资源用整数倍清晰放大。没有高分辨率角色资产时，以清楚的穿戴槽与当前装备名称为主，不把低细节人像拉到半屏。

界面导航符号可以保留简洁矢量，但不要把所有游戏物品也当导航符号。装饰纹样围绕河流、边境记录和工匠刻痕建立少量原创母题；不是给每一块区域加金框、颗粒和模糊。

### 2.2 需要明确的主次层级（P1）

现在大量对象都依靠同样的细边框、低饱和色和小标签表达，网格物品名称主要靠悬停。截图显得整齐，实际扫描却慢。

调整：主要行为有一个稳定强调区；标题、关键结果、实例余量优先。物品默认提供可切换的名称列表；网格保留短名/可访问名称，喷剂同时标瓶号和剂量。已穿戴、不可用、已选中、跟随来源使用各自的符号与文字，不只改边框。空槽不必和有效技能拥有同等视觉重量；槽位坐标不因收敛显示而重新排列。

### 2.3 不能把“灰暗”误当作低对比（P1）

基础正文 `#e6e1d2` / 深底 `#101716` 的理论对比约 **13.90:1**，次级色约 **7.12:1**，没有证据说整套正文都不够清晰。真实问题是小字号、透明度叠加、背景穿透和细线依赖。

资源红 `#b96556` 在深底上约 **4.38:1**，不适合单独承担小号生命数字；条形可以保留该色，小数字使用浅色正文并附生命标签。锁定/失效也不能把完整按钮透明度降到看不清。增强对比应改变实际面板、文字/边界 token，而非只把分隔线加亮。

原型大字模式仍测得部分标签为 **10px**；960 宽 HUD 16 个可点按钮中 **11 个**至少一边小于 40px。正式实现使用有最小字号的语义 token 和实际命中区，图形可小，点击区不能跟着缩小。

## 3. 高频操作：少切页，比少一个点击更重要

### 3.1 绑定快捷槽不应跳走（P1）

v1 的“物品→绑定→K→点槽”虽然按钮上算两步，却打断了行囊比较，且容易把完整知识页当临时选槽器。

改为：物品详情点“绑定”→**行囊底部展开同一组 13 槽**→点目标槽→收起并留在原物品。槽有原内容预览，不为普通覆盖再加确认框；保留清除与明确重新绑定入口。K 负责动作目录和系统整备，仍可做完整配置。

### 3.2 快速查看与完整管理要分开（P1）

普通 HUD 槽点击不应直接把玩家带入 K。点击或明确查看入口打开小型槽详情，展示当前动作、具体来源、余量与形式入口；进入完整编组是次级按钮。点击槽不是左键施法，也不能吞掉关闭后应释放的格挡状态。

F 阅读、搜取和作业优先使用侧边抽屉，只显示这次需要的信息。人物交易和完整行囊可以保留管理页，但高频行为不能都被迫进入整屏页面。

### 3.3 不增加默认高复杂度快捷键（P1）

保留当前轻/重击、格挡、武技、显式元素强化与 F 交互。现有 Ctrl 组合已经有学习成本，不再默认增加 Alt+Shift、多层长按等新操作。拖拽和快捷键是熟练者加速方式，按钮与清楚的鼠标菜单仍能完成主要行为。没有用户测试前，不宣称某种新手势一定更快。

## 4. 战斗读屏与智能施法（P0/P1）

“留白”并不等于把当前形式藏起来。下一次释放至少要能回答：**用哪个动作、哪份来源、会发生什么、扣什么**。

- 当前槽附近显示一行“槽键 / 形式名 / 总费用”，展开时再显示来源身份和详细条件。普通喷剂显示瓶标和 2/3 剂，不能只显示同一个瓶图标。
- 固定与智能跟随各有标记；最近成功元素只影响偏好。当前条件丢失时保留明确失效提示，不把上一次“火球”悄悄变成近身火花。
- 1–3 个候选为紧凑选择条，候选身份稳定。4–8 项的轮盘需补带范围/剂量/费用的实物示例再定版，不能从两选项横栏推断 8 扇区也好用。
- 13 槽是稳定输入位置，不等于 13 个框必须始终同样亮。保留所有键位的定位线索，降低空槽权重；当前槽与危险资源最醒目，不增加第二套物品腰带。
- 武技窗口只显示当前机会和可切换的第二招，不循环播放；附魔涂层与人物 Buff 分开。重式提示在相关状态出现，平时不一直铺组合键说明。
- 受击/失衡、施法接受、来源拒绝、拾取、任务更新按优先级合并；不能让数个通知同时盖住敌人起手。点击/确认/拒绝声音分别短而可辨，跟随 UI 音量与减少动态偏好；只由真实已提交事实触发成功音。

## 5. 实时世界与信息可见性存在结构冲突（P0）

v1 大面板几乎覆盖世界，背景还有模糊。时钟在走只能证明示例时间持续更新，不能帮助玩家看到敌人正在逼近。简单增加“危险红字”依然过晚；也不能为了补偿改成自动暂停、自动闪避或暂停敌人。

修订原则：

1. 快捷查看、选材、短阅读、少量搜取使用轻层，并在实际人物周围保留观察区。布局根据角色屏幕位置和安全边距选择侧边，不把敌人和攻击范围压在面板下。
2. 完整管理是玩家明确进入的行为，标题长期标明“世界继续运行”，清楚保留资源、真实可感知威胁反馈和返回入口。不能保证完整页面里与裸 HUD 同等战斗视野，也不靠缩小文字塞进所谓全功能侧栏。
3. 全部管理页外的 **Esc 输入约定**统一：正常情况下逐层关闭；已有真实受击/感知威胁时，Esc 取消尚未提交的界面准备并直接回世界。已接受的领域动作不因关页退款。警告提示必须反映这一区别，不总写“一步返回”却要求连按两次。
4. 危险可由原领域可感知事实驱动，不由 UI 全图扫描敌人提供透墙雷达。完整页/确认框/输入框/轮盘组合都要复测返回与松键泄漏。

这部分需要 Godot 正常 AI、实际相机和多敌人场景验收。HTML 的“演示敌情”按钮无法替代。

## 6. 交易、制作、搜取与成长的缺口（P1）

十个原型视图不等于核心操作已覆盖。目前缺真实双向交易、搜取转移、拆分数量、休息和存档列表；这些正是玩家游玩中频繁遇到的操作。正式大面积迁移前，至少补下列低保真交互：

| 场景 | 应回答的问题 | 修订重点 |
|---|---|---|
| 多余装备出售 | 卖哪一件、到手多少、商人付得起吗、原绑定会怎样 | 双击加入待售清单或显式卖出；批量只有一次总额结算，不把双击浏览直接变付款 |
| 制造补给 | 缺知识还是缺原料、来源在哪、做几份、装得下吗 | 固定制作区，明确“持有/可访问/本次消耗”差异，不用绿色“齐备”常量文案 |
| 满包搜取 | 物品在哪、什么转移失败、能否拿一部分 | 来源双栏、数量选择、失败留源；专业部位与普通装备分开 |
| 成长/训练 | 看节点是否会花点、效果有什么变化、如何学到 | 预览与提交分离；九分支/40节点用实际信息规模做布局，不只看3个示意节点 |
| 休息/存档 | 等多久、当前危险、保存/读取的具体旅程是什么 | 游戏时间与准备秒数分清；旧档和新旅程边界明确 |

同样需要处理：空搜索、没有适配装备、不可达来源、来源被交易/掉落、超容量、材料在远处箱中、知识未学、失效目标、已学课程与商人缺钱。每种状态说明原因和可行下一步，不只灰掉按钮。

## 7. 扩展性与落地顺序

展示抽象应围绕玩家任务：物品条目、实例状态、成本/产出、比较、主要动作、状态原因、局部结果。不要把交易、休息、法术和 Perk 都塞进同一个动态表单；它们共用视觉组件和请求反馈，仍有不同的信息结构与确认语义。

不增加新库存、快捷绑定、配方、技能资格、报价或任务状态权威。需要输入范围和只读投影，但不预先搭建跨引擎 UI 框架。刷新保持 UID/控件身份，对话服务和区域引用按既有生命周期退出。

修订后的顺序：

1. **先修交互原型的 P0 和任务闭环**：输入范围、当前槽/形式、预览与提交、双击与状态保留；补交易/满包搜取样例。
2. **用一条竖向路径验证视觉与 Godot 接入**：HUD→查看/选材→行囊比较→绑定→回世界。把实际外观、文字大小、提示音与实时危险一起验证，不先铺所有页面。
3. **再迁移人物与生产**：交谈→卖装备→学课程→制作→补给；所有页保持同一状态和明确返回入口。
4. **最后扩展成长、手札、真实地图、休息和系统页**，再做完整旅程和容量压力验证。

## 8. 验收方式修订

上一轮 67 项浏览器检查是有限范围的功能冒烟检查。它检查了绑定、选择不消费、样例制作、根页面水平溢出和返回按钮位置，却没有验证双击成功、Tab 焦点、搜索选择后保留、确认框输入独占或主动作始终可见，因此与本轮发现并不矛盾。

后续不以检查条数或 JavaScript 无异常代表体验达标：

- 每个关键场景同时验证“走通”和拒绝/取消；比较点击前后的实际选中来源与余量。
- 布局检查具体可操作区、裁剪祖先、焦点与主要动作，不只看根页面有没有横向滚动。关键按钮无需滚过故事才能找到，全部槽位在编组状态可见。
- 使用 30 件/100 件同类物、长中文名、两瓶相同喷剂、多个涂层、九分支40节点、长任务与商人缺钱样例。样例规模是待测条件，不是当前内容数量承诺。
- 操作路径记录实际切页、确认次数、误触和无法继续的位置；目标是降低上下文切换，不承诺未经玩家测试的完成秒数。
- 风格评审看实际物品、人物与世界同屏；行为评审看正常 AI、范围失效和真实输入；当前审查不提供这些正式游戏结论。

本轮共记录 14 项针对性观察（含不同尺寸），其中 10 项未满足、4 项满足；具体数据以 [audit.json](design/ui-system/review/audit.json) 为准；未满足项保留作为迁移前清单。原型没有在本轮被修复，不能将 v1.1 文档误认为新版 UI 已完成。

## 9. 后续：v1.1 原型优化已落地

原始 `review/audit.json` 与两张截图保持不变，不把旧未满足项改写成通过。当前 [验收结果](design/ui-system/verification.json) 与 [运行说明](design/ui-system/README.md) 对应新的原型：

- 选中只更新详情和选中态，保留点击节点与搜索；真实双击可使用/穿戴，部位筛选有明确空状态。
- 页面内 Tab 遍历焦点；确认框遮罩、inert 与范围处理阻止底层输入，危险 Esc 直接回世界。
- 13槽共用当前槽选择；数字槽可选材，HUD与K反馈当前形式/费用，失效候选不替身。中键松开和滚轮为显式选择，不消费。
- Perk 单击只预览，明确学习后扣点。
- 行囊内展开固定槽带；主要动作和编组槽不随长说明滚走。100/125%文字均检查实际命中区。
- 补齐样例买卖、拆分、丢弃/取回和按数量搜取，资金不足/容量不足留原物；同一瓶卖出/买回保持余量与原绑定身份。
- 物品默认名称列表，可切网格；纸娃娃缩为真实样例穿戴与已有像素身体示意，字号与命中区有下限，增强对比修改实际面板/文本token。

这完成了原型优化阶段。实际角色rig、正常AI、输入穿透到世界动作、存档和领域服务仍需下一阶段在Godot验证；原型中“时钟继续”和“演示敌情”不是这些结论的替代。
