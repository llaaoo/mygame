# 灰河谷 UI：成熟作品对标与下一批优化

2026-11-12。基线：`e8d1af5`，对应 [v1.1 设计](UI_SYSTEM_DESIGN.md)、[交互原型](design/ui-system/README.md) 与正式 Godot 界面。初次对标为资料调研和方案评估；随后经用户授权落实v1.2交互原型，见第12节。没有修改或试玩商业游戏，正式Godot界面与玩法本轮未改。

选择七款成熟 RPG/动作游戏，比较具体机制，不做评分排名。高口碑不等于每一处界面都适用；外部事实以官方指南、发行商说明和开发者补丁为依据，下文“灰河谷建议”是本项目的设计判断，不表示这些作品都采用相同做法。

## 2. 当前差距应分三层看

1. **规则已有，展示尚未统一**：正式代码已经具备属性派生预览、物品比较、材料用途/已知配方、施法解释链。原型是视觉与操作样例，不能把它的简化误判为正式系统缺失。
2. **操作已有，复杂规模未充分验证**：v1.1 能操作绑定、买卖和搜取，但示例只有少量物品、一个可购买 Perk、几个地点。141项检查不证明100件装备、九分支40节点、多状态战斗、室内多层地图同样好用。
3. **值得新增的玩家能力**：出发整备清单、制作目标固定、按UID收藏/待售标记、规则词条解释与返回链、分级通知和状态原因。它们应连接现有系统，不成为更多独立主菜单。

| 已核对的正式基础 | 可复用部分 | 需要改善的呈现 |
|---|---|---|
| `ui/actor_inventory_screen.gd` | 实物UID、直接绑定、已知材料用途、装备比较 | 与新行囊壳整合，不退回另开K；“用途”能继续走到实际配方/配置，并保留返回上下文 |
| `ui/character_progression_screen.gd` | 主属性当前/下一级派生值、有效值、明确学习按钮 | 统一说明来源；装备变化、Buff与属性自身贡献分清，不只放静态数字卡 |
| `gameplay/abilities/combinations/conditional_cast_controller.gd` | `CastPlan`的结构化解释，含来源、材料、效果与总费用 | 主层给结果，展开给原因，进一步链接已知规则；不要在UI重写施法计算 |
| `docs/CONTROL_SCHEME.md` / `docs/UI_AND_INTERACTION.md` | 既有输入、实时界面、直接绑定、材料用途与小窗覆盖 | 新方案接入时保持这些能力，明确原型操作与正式游戏当前操作的区别 |

本轮只做静态核对和既有证据评估，没有因此重新宣称正式游戏全量测试通过。

## 3. 优先优化一：从“加多少数值”变成“改变什么打法”

**参照：艾尔登法环的解释入口；结合本项目已存在的属性与动作查询。**

当前原型装备比较只对同名数值做差，正式页另有动作说明和派生预览，信息尚未形成一个帮助配装的结论。玩家应在换装备前看懂：得到什么、失去什么、哪条已有连招或来源不再适用。

建议装备详情固定显示：

- **基础差异**：伤害、防护、稳定、重量，明确单位及有利方向；攻击体力下降是收益，重量上升是代价，不统一把正数涂绿。
- **实际角色影响**：有真实查询支持的体力费用、负重阈值、恢复与准备变化。物品裸值、角色有效值、临时增益分栏，不把它们相加两次。
- **打法兼容**：刀换弓时列出实际弹药要求与不再满足的刀剑连招；比较不同武器家族时不强行给不存在的共同DPS排名。
- **实例状态**：当前涂层、剂量和强化属于哪一件；比较预览不能把涂层转移到候选武器。

解释只读领域查询。不能为计算预览真的换装、临时扣资源再回滚，或从文案用 `parseFloat` 反推出规则。规则暂不支持的结果明确缺省，不伪造精确数值。

验收：一把更轻但伤害更低的武器，玩家能同时看到两个取舍；预览前后UID、资源、冷却、涂层不变。对比刀/弓不会把不同射程或不同攻击周期硬比较成一个绿色箭头。

## 4. 优先优化二：整备与制造应帮助玩家形成目标

**参照：怪物猎人的出发整备；以下清单和配方固定为灰河谷的适配建议，不作为未核验的对方功能断言。**

目前原型告诉玩家“能做火石”，却不能让他把“准备一次北路探索”保留为明确意图。每次回镇都要重新想一遍食水、布料、阵材与训练。

建议在现有行囊/手札中加入小型“本次准备”，首版最多固定3个目标：

- 固定已知配方或手动补给目标，显示“目标/身上可用/其他已知来源/缺项”。这不是新强制任务，不自动发物品。
- 原料属于多份目标时显示需求冲突，例如布料同时用于检修与抹布；**标记保留不会凭空预留或锁住库存**。制作仍由原服务检查并由玩家确认。
- 材料用途只列已学配方、已知技能和已获得线索；来源未知就显示未知，不从全目录揭示未探索资源点。
- 点缺项可查看已知来源或现有商人/作坊入口，服务仍受距离、当值与危险限制；不是任意地点远程购物。
- 没有魔力的旅人优先看到武器、食水、工具与手工方案；不把锁定法术占据默认教学流程。原型Q/R锁定槽只是阶段演示，不能作为正式新档自动配装依据。

不引入“一键准备完整连招”“加载行装自动换瓶/补阵”。若未来保存整备方案，默认先比较差异，再明确选择是否改变原有快捷绑定；继续使用 `QuickslotLoadout`。

验收：布料被消耗、放包、出售后清单立即反映实际可访问数量；打开清单或切区不补货，不改变知识和绑定，不把已知远处库存当成身上可用。

## 5. 优先优化三：批量整理应减少重复，但保留准确性

**参照：BG3 的键鼠多选与待售操作。**

原型已有待售清单，但还依赖逐件加入，缺少大量战利品的组织能力。建议同一物品列表支持“最近获得/名称/重量/价值”排序、收藏、待售与明确的批量模式；收藏和待售按具体UID，不把两瓶同名喷剂合成一个模糊条目。

- 收藏、已装备、当前绑定来源和准备目标材料有清楚标识，批量默认不选这些对象；玩家可明确改变选择，UI标记不能越过领域中的可卖/不可卖规则。
- 批量先显示件数、总重、报价、商人钱袋与容量，以及会失效的绑定；一次明确提交，不要求每一件都弹确认框。
- 不把“参考价值”伪装成当前商人的报价，不显示无依据的“推荐全部卖掉”。
- 保留当前Shift比较。首版用选择模式+复选框，Ctrl多选可仅在界面范围内提供；不直接照搬会与比较/武技冲突的修饰键。
- 必须先定义批量事务语义：若沿用逐件事务，结果逐件回执并明确部分完成；若承诺全成全败，就由库存边界提供真正整批事务。循环调用按钮不能假装原子结算，失败也不能自动重试到成功。

验收：同名不同剂量喷剂、多件强化装备和受保护材料混在100项列表中，选择、数量和来源保持；关闭/重开菜单不默默结算，失败物品能准确定位。

## 6. 优先优化四：HUD需要“情境”，也需要玩家控制

**参照：艾尔登法环的Auto HUD和巫师3的探索隐藏设置。**

v1.1固定显示资源、完整快捷栏、当前形式、目标与操作提示，清楚但变化不大。建议先做“标准/探索精简/战斗完整”显示预设，并允许单独保留关键项；这只是显示策略，不改变难度或模拟。

| 情境 | 强调 | 收敛 | 必须守住的边界 |
|---|---|---|---|
| 安全探索 | 方向、当前交互、短目标、明确需要的补给状态 | 已熟悉操作说明、空槽装饰、满资源数字可减弱 | 槽位位置不移动；不自动隐藏低生命、失效来源或关键负面状态 |
| 战斗/当前瞄准 | 生命/体力、当前槽来源/费用、目标与武技机会 | 任务长文、普通拾取、长教学 | 不增加第二套快捷栏；不借“智能”替玩家施放 |
| 当前来源失效 | 原形式身份、一条原因、可选下一步 | 重复的同类拒绝 | 不用另一个合法形式占据旧悬停位置，不自动换瓶 |
| 整备/交谈 | 当前主要操作、实例、成本与危险返回 | 与这次任务无关的世界标签 | 世界不暂停；完整页无法保证裸HUD视野，不能隐瞒风险 |

稳定位置与图标身份优先于炫目的布局切换。隐藏不停止AI、资源恢复和Buff，显示层只读实际事件与可感知状态。若多种模式同时触发，先处理危险/失效，再处理探索美观；玩家可选择持续完整显示。

验收：进入战斗时手边的槽没有跳位；低体力、涂层将尽和来源失效不会因探索精简消失；刷新隐藏HUD不产生重排或每帧格式化热点。

## 7. 优先优化五：战斗状态要有一套可学习的语言

**参照：战神的分类提示与音效，最后生还者的可视替代。**

当前原型只有一个静态Buff、涂层秒数与文字目标，不足以证明复杂战斗可读。后续应统一表达：

- **动作阶段**：准备/有效/恢复/被打断，与真实共同执行链对应，不能由动画播放自作主张判断命中。
- **异常积累与已生效状态**：积累使用未闭合进度，生效使用状态图形和剩余时间；不能把两者都叫“中毒”。
- **人物增益、武器涂层、地面阵能**：不同归属标识。阵能消耗造成的时长变化读取真实结果，不把地面剩余时间误写成玩家永久Buff。
- **受击与危险**：只对真实命中或已感知的威胁提供方向/类别，不能照搬某些辅助模式得到透墙敌人位置。
- **结果声音与文字**：接受、拒绝、格挡、失衡可辨；提示音可独立调节并在说明页试听，重要声音有文字/图形替代。成功音只来自已提交事实。

通知按“立即危险/失败原因→动作结果→拾取/任务更新”分级；重复普通消息合并，保留有限近期记录供重读。不要让一个新的拾取toast覆盖刚出现的来源错误，也不要让日志回放再次发奖励。

验收：两个敌人、两种异常积累、武器附魔和脚下法阵同时存在时，仍能分辨三种归属；静音或不看颜色时，关键结果仍可辨。减少动态不抹掉必要状态。

## 8. 地图与手札：提供方向，不代替发现

**参照：对马岛让环境线索参与导航；巫师3的图标过滤。**

建议把个人路标、亲历地点、听闻线索和当前正式目标分开，地图卡片回答“知道什么、从哪里知道、下一步可以做什么”。

- 亲历地点可精确；传闻是范围/文字线索，不能伪装成已确认坐标；未知内容不先铺满问号。
- 从手札查看地点、再返回时保留原记录、滚动和筛选。阅读线索、获得证据、完成目标不混成一个勾选状态。
- 室内入口、楼层、返门与室外目的地使用真实地图连接；“距离很近”不能掩盖隔墙、跨层或需出门。
- 世界标识优先依靠道路、河流、门牌与实际地标。辅助方向只指已知目标，不为无魔力旅人附送超自然导航。

验收：一条未证实线索不会直接揭示机关答案；入室后目标不会悬在错误楼层；换区后沿已知返门能回到目标记录。

## 9. 视觉成熟度与可访问性还需要什么

**参照：战神独立的文字/图标尺寸与响应布局，最后生还者的设置预设。**

当前深色、黄铜、清晰列布局可继续使用；下一步应强化灰河谷的工匠刻痕、河流与档案语汇，而非给所有页面增加卡片、金边、颗粒和模糊。物品实体轮廓与导航图形分工，真实角色装备预览保持比例；示意像素身体不等于正式外观系统已接入。

- 设定主/次/危险/选中/不可用的语义token与实际字号下限，在明亮、暗处、水面和密集植被中检查；不是只看静态暗底。
- 阅读字号、HUD与图标可分开调整，先提供少量好用预设，再给必要单项；不把设置页扩大成几十个无组织开关。
- 重要解释可以固定并用鼠标/键盘进入，不能只有悬停才读得到；打开词条后可返回原物品/技能，不再走一遍搜索。
- 可切换的按住/点击式选择继续共用同一意图，取消有清楚死区/关闭入口；不新增默认复杂组合键，仍保留左键攻击、右键格挡、F交互。
- 改键后的实际键名、帮助和图形提示共用 `InputBindings`；不要把原型写死的键表直接迁入Godot。
- 普通新档、未觉醒、已觉醒、有大量知识的存档分别检验默认信息量。不能只用满能力角色证明首玩清楚。

现有正式UI文档曾覆盖960×540等小窗；新原型目前验证基线是960×720。正式接入时必须对照现有窗口支持范围复测，不能把原型通过的较高最小高度当成可以退回旧可用性的理由。手柄仍按用户决定暂缓。

## 10. 建议实施次序与范围控制

| 阶段 | 具体交付 | 依赖与验收 |
|---|---|---|
| 第一批：正式竖向接入 | HUD→当前槽/来源→行囊比较→原位绑定→回世界；复用已有派生/解释/用途查询 | 正常AI、真实输入、来源失效、区域切换；不再先做一轮覆盖全部页面的新HTML框架 |
| 第二批：决策支持 | 配装实际影响、词条解释/返回、少量准备目标与缺项 | 有领域查询才显示；预览不改变实物；解释不泄漏未知知识 |
| 第三批：大量物品操作 | 多选、收藏/待售、最近获得、批量回执 | UID状态连续，事务语义明确；满包、缺钱、部分失效的混合选择 |
| 第四批：战斗与探索表现 | 情境HUD、状态语言、通知优先级、视听提示、真实地图线索分类 | 静音/低动态/密集战斗与多种背景；已知信息边界 |

本次不根据“某款3A这样做”修改战斗数值、增加内容数量、开启暂停、自动补料或扩展手柄。若开发资源只能先做少量内容，优先完成第一批并挑第二批的“比较影响”和“准备缺项”，不要把目标清单再做成一个庞大独立系统。

## 11. 验证应记录玩家任务，而非只有检查条数

新增验收场景应包含：

1. 普通人新档第一次换装、分辨指定瓶与普通材料、绑定并返回世界；没有主动法术也能理解主循环。
2. 同一战前状态中明确选形式，条件失效、取消、重新选择；不因UI帮忙改变可执行动作或返还已支付费用。
3. 100项含同名不同余量、不同强化与涂层的列表，查找、比较、收藏、多选、出售和回到原视图。
4. 准备目标引用同一份布料；实际制作、丢弃、放包、服务关门后，缺项和来源及时更新。
5. 多敌人+状态+法阵+低资源，分别在静音、减少动态、大字和现有小窗范围下验证。
6. 存档重进与区域切换后，物品身份、已学知识、真实剩余时间维持；临时解释窗口和未提交准备不恢复成动作。

记录每项的切页次数、重复搜索、误执行、失败后的去向及未能完成的步骤；计时目标在有正常AI和真实参与者数据后设定，不捏造“比某3A快多少”。本轮没有执行上述新增游戏验收，也不把原型既有141项通过扩展成这些结论。


## 12. v1.2原型落地与正式迁移契约

2026-11-12，基于 `28ac7ea`。按用户授权完善现有HTML原型，没有新增Godot规则或更改游戏存档。实现范围与[实际运行方式](design/ui-system/README.md)一致；历史v1.1与原复审证据保持。

| 决策 | 本次可操作结果 | 正式Godot接入边界 |
|---|---|---|
| 配装取舍 | typed数值、单位/收益方向、弓的弹药与失去刀剑武技条件、可返回的规则说明 | 接现有装备/成长/动作查询；不解析文案、不临时换装、不把样例裸值当角色有效值 |
| 三目标准备 | 共享材料求和、制作成功进度、丢弃/取回后的缺项、已知寄存不算身上 | 意图只存目标定义与数量，缺项由库存和已知配方投影；加工事实推进目标，不能成为第二本库存/任务账。放下背包、服务关门等仍须正式模拟 |
| 收藏与待售 | UID标签、多选安全默认、同名瓶区分、明示保护、载入报价后整批确认、买回恢复原件 | 元数据引用UID，不改所有权。实际操作仍走InventoryService；预览到提交间再验来源、报价、资金和容量。混合失效整批拒绝；部分成功只允许未来另做显式模式 |
| 情境与通知 | 槽位不移动、探索减字、危险覆盖、积累/人物状态/武器/地面分层、失败优先、有限近期日志 | 危险只用可感知事实；UI开关不能停止AI或计时。提示订阅已提交事件，日志只读，不触发资源动作 |
| 视听与尺寸 | 菜单/HUD独立尺度、125%大字、静音文字保留、默认关闭的合成音试听 | 接统一偏好与表现层；关键声音有文字替代。实际背景、动效、设备听感和960×540仍需游戏内检查 |
| 地图与解释返回 | 亲历/听闻过滤、来源、宽泛传闻区域、禁精确路标、视图上下文保留 | 读真实发现和地点引用，不凭UI坐标创建发现；室内楼层、返门与跨区连接本次未模拟 |

验证：原有141项流程回归和新增93项决策流程均通过，使用Linux系统Chromium、Playwright真实键鼠事件；三尺寸960×720/1440×900/1920×1080，新流程均覆盖125%字号与独立HUD尺度。100项夹具具有独立UID、长名称、变化剂量/强化，明确临时上限500/120格。它验证查找/排序/收藏/返回，不等于100件真实存档交易、所有Perk或密集战斗已验收。状态是静态夹具，声音只验证浏览器路径；未测正常AI、真实计时、保存恢复、玩家耗时或目标设备性能。证据：[基础](design/ui-system/verification.json)、[新增](design/ui-system/decision-verification.json)、[文件散列](design/ui-system/evidence.json)。

正式迁移仍按第10节次序推进。第一条竖向验收必须在隔离新档、正常AI中完成：打开行囊→比较并查解释→绑定指定瓶→回世界选形式→条件失效明确拒绝→手动重新选择。记录实际输入、资源和UID结果，再验证跨区与保存重进。HTML模块与样例数值不复制到Godot；共享数据、动作规划和事务仍归现有所有者。
