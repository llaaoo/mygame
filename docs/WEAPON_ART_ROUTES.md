# 连招窗口与共用武技键

2026-11-09。武技主流程改为“亲手轻/重击 → 满足连招条件 → 短窗口按共用键”，学习后无需逐一占用快捷槽。默认共用输入 **Ctrl+左键**（V保留为可改键的速发入口），可在设置中的“共用武技键”改键；Q/E/R与1—0仍是独立的法术/物品/动作快捷槽。

## 当前路线

轻击为短按左键，重击为长按左键（0.32秒）。共用鼠标武技也分短按速发、长按重发，Shift显式释放附魔。见[按住式武器操作](WEAPON_HOLD_INPUT.md)。每一击和最后发动武技都需要真实输入，按住不会自动连招。

| 武器 | 实际轻击 → 重击 → Ctrl+左键 | 另一条路线，同样用Ctrl+左键 |
|---|---|---|
| 刀剑 | 破势斩 | 连续两次轻击，末击有效命中 → 截势斩 |
| 长矛 | 贯步刺 | 连续两次轻击，末击有效命中 → 追身贯刺 |
| 战杖 | 压阵横扫 | 连续两次轻击，末击有效命中 → 回旋压阵 |
| 弓 | 蓄力穿射 | 一次轻射有效命中 → 追隙穿射 |

轻重击路线要求两次实际挥出/离弦，可挥空或被格挡；保留真实动作承诺和费用，适合在对方防守时准备破势。接势路线要求末击对战斗角色造成未格挡正伤害，挥空、挡住或打普通场景物件不提供此分支。动作和取舍继续读取[接势武技](MARTIAL_FOLLOWUPS.md)定义，速发保留其原伤害/时序/费用；重发使用额外的显式Resource变式。

**窗口从最后一击完成收招后开始**：轻重路线1.1秒，接势路线0.9秒。之前动作之间必须在原武器接续间隔内输入；一旦下一击被接受，不会因其前摇较长而中途丢掉前一击记录。重击仍结束普通轻击段落，但参与武技序列。

最后一击后摇末端、输入确实可缓存的最后350毫秒会预告“收招后”；此前不显示可发动提示。手动缓存V后，完成收招才尝试发动，不提前扣武技费用、不取消剩余收招。没有形成路线或尚未到达可缓存阶段时按V会说明未发动并提示K查看条件，不会等候多秒后自动施放。

例如学习破势斩后，短按左键 → 长按左键 → 完成收招，HUD显示“Ctrl+左键 · 破势斩 · 1.1秒”；再短按或长按Ctrl+左键。若改为两次轻击且末击有效命中，显示“V · 截势斩”。新招式可声明其他短序列，仍使用同一个共用键。

## 来源、选择与取消

- 共用输入在按下时锁定武技ID、路线和组成动作的family令牌；再执行时重验同一窗口、当前实物UID、知识、费用、冷却和来源。到期、换装或继续出下一击后，旧请求不能改放另一招。缺体力/缺箭/冷却中的路线保持原选择并显示原因，不偷偷改用较便宜的分支。
- 同时匹配时先选较长序列，再按内容显式优先级选择；注册校验拒绝同武器类型、同序列、同优先级的歧义。匹配只看已学会的武技，不授予隐藏知识。
- 轻击、重击和武技各自消费真实体力。弓的轻射、重射和随后武技各用一支实物箭，所以轻→重→武技总共三支；离弦才提交，打断不凭空消耗或生成箭。MP规则不变。
- Shift+共用武技键显式请求释放同一把真实武器的附魔；在输入时锁定涂层状态，实际挥出/离弦时提交。缺涂层的预览灰显；不会自动涂附、补阵或换源。
- 成功发动武技立即消费窗口，与同一武技旧入口共用冷却。HUD随后显示招式起手/挥出/收招及真实冷却，不需要保留一个快捷槽才能查看。普通走位与冲刺可在窗口内调整距离，仍支付实际冲刺费用；过期、格挡开始、闪避、施法、使用物品、交互、开菜单、离区、死亡、休息和读档清理序列。
- 输入历史最多四击，属于角色短期状态，不写Resource、装备或存档。旧箭只能确认仍保留的同family事实，不能恢复被清理的记录；迟到命中不会改变已捕获的V请求。

原有独立武技绑定保留，供旧存档和习惯继续使用，不自动清空用户槽位。主流程不再要求这些绑定；K中右键原槽可自行清除，把位置留给物品或法术。旧Ctrl+独立武技键固定常规形式的规则只用于该旧入口，共用键始终由连招路线决定形式。

按键布局升级为v7。旧默认Ctrl+左键重击迁移为按住式重击，共用武技默认Ctrl+左键，V作为兼容速发入口。旧自定义占用V时不抢占它；已有自定义武技键保留，HUD与设置显示实际映射。合法的旧自定义、E与1的独立性和鼠标攻击/格挡保持原规则。

## 架构与接入

沿用Godot Resource定义、RefCounted运行值和Node物理执行器的职责划分：

- `MartialRoute`是短序列定义，配置`sequence`、常规/接势形式、无需命中/末击/每击命中要求、独立窗口和显式优先级。最长四步，窗口为有限正数且不超过3秒；`MartialTechnique.art_routes`登记路线，不增加新的执行器或库存权威。
- `WeaponArtState`唯一持有本角色的轻重击顺序、UID、family、实际挥出、命中和完成时间。由ActorActionController在已接受动作、实际提交和完成时推进；UI/输入/AI只查询。`WeaponComboState`继续只管普通连段位置，旧接势查询也从同一命中记录派生，不另存一份命中标记。
- `weapon_art_view / capture_weapon_art`共用于提示、核心输入与AI；执行仍转为原TECHNIQUE Action，走原体力、知识、冷却、箭矢/附魔事务和CombatExecutor。共用键是核心动作，归InputBindings管理；不建立第二个快捷槽列表，也不写QuickslotLoadout绑定。
- AI可优先利用已形成的共用窗口，通过同一捕获/校验执行。既有独立武技的策略保留原兼容语义，不授予新知识或免费动作。

新增同类武技时登记知识/来源和若干MartialRoute即可接入同一键；新的动作机制才扩展原执行链。不用为每种连招新增键位、脚本分支或组合宏。

## 验证与范围

`weapon_art_routes`通过真实接受/挥出/完成推进四类轻重路线，覆盖无需槽位、顺序错误、命中要求、普通与武技独立截止、未挥出/打断、缓存、过期、UID/令牌失效、资源重试、Shift真实涂层与波、保存恢复、歧义/非法配置。是受控领域边界测试，不代表战斗平衡。

`weapon_art_input`使用实际Godot键鼠事件走四套左键→Ctrl+左键→V，验证自然体力/冷却、弓三支实物箭、按住不重复、无独立武技绑定、已有法术槽保留、改键H、实时菜单阻断及F5/F9清理。世界与背景敌人保持正常AI；验证轻击命中分支时，一个目标停止移动和决策，装备/知识/安全位置由fixture提供，不作为自然开荒或真人对战验收。
