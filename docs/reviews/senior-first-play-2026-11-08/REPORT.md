# 灰河谷 Demo：资深开发者独立首玩与定向验证

日期：2026-11-08。评审基线：`e6c1685fed761fab72052e151d50277262a64f8e`。本次只有一名试玩子 agent，父 agent 未操控游戏或提供路线答案。未修改游戏代码。

## 结论与适用边界

这个版本已经表现出一个值得继续发展的动作 RPG 基座：材料制造改变实战方式，敌人的穿戴成为真实战利品，战利品又进入穿戴、容量和交易决策；机关成果能够打开下一层和返回捷径。我的一次自然决策是卖掉大量施法原料，换一把短刀再出发；后来又真正用火阵与火花完成远射。这些都是系统相互改变玩法的证据，不能把本作简单归为“堆了一批独立功能”。

目前阻碍首次体验的主要问题是**玩家得到的行动依据有错误，界面状态又未能解释真实条件**。猎营说旧窖在西侧，入口实际在东北；墓道封条缺净化前置，却告诉我寻找图纸。我确实据此向西寻找、怀疑误入后期路线并离开。修正这两点，比再增加一个区域或几十件材料更能提高现有内容的可玩性。1152×648 下的作业面板越界和战利品页单字竖排，也直接损害整备过程。

**未通关巡河终章。** 首玩阶段没有完成一整条机关链；封存观察后，才阅读实现并用同一正常存档走通“墓道净化架→封条→钟下回执→遗钟→新捷径”，返镇交付名字支线。不能把这段知情验证包装为首次玩家自行发现，也不能把本次约 57 分钟的输入日志跨度当作 57 分钟有效内容，更不能据此认证“两小时 Demo”。

未发现足以确认的 P0。以下 P1 指会误导推进或妨碍关键界面的高影响问题，不代表死档。战斗精确手感、反应窗口、设备性能、听觉与所有高级组合均不在本次有效验收范围。

## 方法、环境与证据可信度

- Godot `4.6.3.stable.official.7d41c59c4`；Linux 云环境；Xorg dummy `:93`；原生 Godot 窗口，1152×648，`gl_compatibility`。音频驱动为 Dummy，**没有听觉验收**。
- 启动：`GRAYRIVER_DISPLAY=:93 python3 /tmp/grayriver-senior-runner.py fresh-20261108`。该启动器直接运行 `res://grayriver.tscn`，不是 probe 场景。完整命令和 XDG 路径见 [session-manifest.json](evidence/session-manifest.json)。
- `XDG_DATA_HOME/CONFIG_HOME/CACHE_HOME` 分别指向 `/tmp/grayriver-senior/fresh-20261108/{data,config,cache}`。初次运行三者为空，未复制存档，未传启动器的 seed 参数。保留了[新旅程开场](screenshots/001-fresh-opening.png)。初始空目录是当时操作记录，没有独立保留目录清单；不把“没有 seed.sha256”单独当作完整的新档证明。
- 实际输入经 libXtst/XTest 发给操作系统：WASD、真实鼠标、F、快捷槽、菜单和 F5。截图为 Xorg root 的原生画面。没有调用领域 API、瞬移、改任务、补材料、冻结敌人、改属性、读取屏幕外敌人位置或用测试夹具通关。
- 初期误读了 README 前 100 行，接触了公开玩法概述。因此这是“未预读地图/实现/攻略的独立首玩”，**不是完全零信息盲玩**。首玩期间只读输入适配工具，没有运行其隐藏快照，也没有读取剧情/地图 JSON、玩法实现或旧报告。
- 首玩封存后，按父 agent 明确授权进入知情验证，才查 `grayriver.json` 和相关实现，取得机关位置与依赖信息。此阶段的寻路有源码帮助，操作与消耗仍由真实输入完成。首次搜索意外返回一段既有开发验证文档摘要，发生在封存之后；它未参与首玩判断，后续未继续阅读旧报告。
- 部分近战使用短时可见画面辅助：识别截图中的敌人血/蓝条，移动、瞄准、普攻、格挡；有明确时限，无目标约 3 秒停止，死亡/模态出现即停止。**未自动布阵、备料、补阵或执行法术连招**；旧脚本中未调用的 ranged 分支也从 v2 删除。探索和材料决策由本 agent 作出。原生逐次输入与视觉辅助证据分别存放，不能称为真人手动盲玩。
- 辅助假定玩家在屏幕中心；摄像机夹边后该假定失效，v1 对极低血条也有误检。相关失败与死亡保留，但不据此评价 AI 强弱。截图后推理的几秒至十余秒，游戏仍在运行，也会让敌人靠近；这是测量限制。
- 首次尝试 OS 关窗未使 Godot 退出，误启动过短暂的双实例；发现后关闭两者，再从刚才 F5 生成的同一存档恢复，双实例期间没有继续游玩。旧日志首段被覆盖并含 NUL，`runtime.log` 不是完整连续的时间证据，原生输入记录仍在。之后均确认单实例。退出验证采用 **F5 后 SIGTERM、再启动**，并非游戏内正常退出菜单测试。

### 首玩时哪些东西自然被用到了

**火阵不是纯说明文字。** 炭屑与晶砂制火石，火石改变铭刻来源，站定形成阵，阵内改变火花射程，每次释放又消耗法阵寿命。这次以阵地换安全距离、以准备换输出的取舍成立。树木真实遮挡也使“站哪里”有意义。应保留这条小而完整的教学链，优先让更多新玩家成功经历它。

**经济给了我真实的替代策略。** 我没有自然想到更多高级组合，而是把原料变成短刀。随后发现敌人有同类刀和皮甲，击败后能穿戴与回收，装备外观和库存形成一致的理解。交易不应只作为换币按钮：这次出售晶砂也减少了后续火石供应，有机会成为持续的准备选择。

**饮食与休息进入了远征循环。** 前两次死亡后主动花饼和水休整，后来发现安全停留也会慢慢恢复生命。首玩读到水、喷洒与饮用共享实物，意识到水不是无限法术弹药；但没有自然完成水洗毒或锅边节省燃料的实战。口袋早早12/12、背包逐渐增加，又使搜刮和材料整理有实际用途。

**高级组合没有自然转成策略。** 看到了凝神、塑形、聚能投射等说明和材料轮盘，但我最需要解决的是安全读说明、确认槽位/材料、找到目的地和活着完成首次火阵。它们暂时像后备知识，尚未成为“看到某类敌人就会考虑的对策”。不能因此判定这些系统无深度；能判定的是本次首玩没有建立其使用动机和可重复的心智模型。

## B 阶段：查实现后的定向验证

这是知情补测，路径位置与依赖来自内容文件；没有改存档或领域状态。

1. 查到墓道净化架实际在东南，封条依赖 `demo.bell.cleanser`。同档返墓，处理此前未见到的第四名上层守备兵，实际搜刮；不把它补算进 A 阶段。
2. 站在净化架旁，界面显示苦叶持有7、布料4。按F作业，站定6秒，成功付苦叶2、布料1。装置变绿，提示“重进本层时中央毒地停止渗出；北侧封条已经可以处理”。本次只确认完成提示和成果保留，没有逐格测毒地伤害停止。
3. 去同一扇封条：原先的“先寻找图纸”消失，金属2时可操作。站定6秒，付金属1，门开启，实际进入钟下封室。
4. 读取南侧“泵工最后的回执”，获得晶砂、布料与回响墨等现场供应。一次下层辅助战斗因画面识别与摄像机边界失效后死亡，真实返镇再恢复，**第7次死亡**。
5. 重返墓道，净化架仍绿、封条仍开；读东南“石壁上的无名者”。再入下层，绕柱走中线，只击败接近遗钟的一名守猎人，未全清下层。
6. 遗钟作业页显示晶砂2、布料4，选择手动校准，站定6秒，付各1。装置变绿，提示回执译出、下一站泵站，获得守护粉/币等奖励；“旧运尸坡返回西林”捷径开启并**实际使用**。
7. 用游戏内站定3秒的正常撤回回镇。站定吃饼、喝水成功，默认快捷栏的饼2→1、水2→1；此前紧接移动会打断，不能把未消费误判成物品键失灵。
8. 在委托页交付“遗钟·未被抹掉的名字”，从可交付变已完成；再到炉灶站定3秒制作烤饼，谷粮3→2，饼1→2。没有制作茶/炖汤，未完成“行路者的热饭”。
9. F5保存、关闭进程后同 XDG 原生重启，完成支线仍显示已完成。仅在全部游玩结束后，以独立只读 FileAccess 脚本核对最终保存值，确认死亡7、四项遗钟链事实存在、名字支线已交付、终章与烽堡信号未完成。没有用该脚本继续游玩或产生事实。

后续收益并非只是一条日志：下层是独立区域，回执给了下一机关的具体信息与材料，遗钟打开真实出口，名字记录能够回镇换成长奖励。当前手动作业三次都是“有材料→按F→站定6秒”，若战场已经处理，作业过程本身缺少不同的决策；这是深化空间，不是本次确认的功能错误。

## 问题清单与可实施修正

### P1-01：旧窖方位错误，直接把首次探索带离关键知识

**实际现象 →** 猎营记录原文“猎营西侧的旧窖藏着档案”：[完整原文截图](screenshots/014-hunter-original-fulltext.png)。我多次向西寻找，发现西侧墓道并进入，随后继续在西林绕行；A 阶段未进入档案窖。没有把所有迷路都归于这句提示。

**玩家影响 →** 档案窖承载震荡、图纸和调度令，方向错误会让首次玩家延迟接触后续关键信息，还会把缺技能/缺前置误解成自己选错难度。

**原因假设与核实 →** 高置信度，已核实内容数据：猎营坐标 `(-3000,-1200)`，窖入口 `(-2600,-1800)`，即东北。见 [grayriver.json:78](../../../content/frontier/grayriver.json#L78) 与 [入口:811](../../../content/frontier/grayriver.json#L811)。错误是文案与布局不一致；不推断它是最近哪次改图造成。

**最低可行修正 →** 将句子改为“猎营东北侧、靠近祈坛的档案窖”，在实际岔路放一个可见的档案窖标识；保留未发现区域的探索感，不必直接揭全图。

**长期方案 →** 导航句引用地点ID/地标关系，统一地点名与方向；静态校验可检查写明方位的成对地标，或至少为改布局建立需复核的提示清单。

**验收标准 →** 新档只读手册与猎营记录，不看攻略，能沿提示找到窖入口；记录、路牌、地图命名一致。测试不能直接传目标坐标代替寻路。

### P1-02：缺净化前置被解释成缺图纸，使玩家主动放弃可推进路线

**实际现象 →** [封条原状态](screenshots/012-tomb-door-requires-knowledge.png)完整显示“尚未掌握检修步骤，先寻找图纸”，持有金属2。我查看K发现没有冲击，结合“图纸”判断需要先去别处；实际上根本不需要为手动路线学冲击。B 阶段付苦叶2、布料1完成净化后，[同门立即可操作](screenshots/017-seal-same-site-now-ready.png)，金属条件未增加。

**玩家影响 →** 游戏把“本层还有一个装置没做”说成“去别处找知识”，阻断当前目标的可解释性。它也掩盖了手动检修原本能服务缺技能玩家的设计价值。

**原因假设与核实 →** 高置信度，已核实：[FieldWorkSites.reason:10](../../../gameplay/exploration/field_work_sites.gd#L10)对所有 `required_claims` 缺失统一返回找图纸；[封条依赖:2293](../../../content/frontier/grayriver.json#L2293)实际为 `demo.bell.cleanser`。

**最低可行修正 →** 该门显示“先恢复东南侧净化架；材料已足够”，同时明确“火→冲击”与“金属1手动6秒”是两条可选路线，未学冲击不应影响手动路线说明。

**长期方案 →** 让条件提供类型化的拒绝理由/可显示目标：知识、装置状态、材料、附近威胁、距离分别解释。UI、按钮禁用和日志复用同一只读查询结果；不要按 claim 字符串猜文案，也不要为每扇门复制特殊判断。

**验收标准 →** 净化前点门，准确告知净化架；净化后金属足够可开，缺金属时明确数量；只缺冲击仍可手动开；法术和手动最终写入同一成果、重复交互不再收费。需新档原生输入复测。

### P1-03：小窗口关键界面布局失效

**实际现象 →** 1152×648 下，[篝火作业面板](screenshots/031-rest-panel-overflows-right.png)超过右边界，部分说明不在可读区域；短一些的[净化作业面板](screenshots/015-cleanser-ready.png)能容纳，表明内容长度影响布局。[战利品页脚](screenshots/010-loot-panel-clipped-footer.png)被压成单字竖排，延伸到窗口底部之外；空结果文字也出现过单字换行。T取全部仍可用，不能说整个拾取失效。

**玩家影响 →** 玩家需要比较耗时/消耗、确认当前能做什么时，偏偏看不全规则和操作，容易依赖记住热键来补救。

**原因假设与核实 →** 中高置信度，代码支持但未做控件布局调试：作业面板是固定右下偏移，`OptionButton` 直接填完整长标题，最小宽度可能把父面板撑出屏幕；见 [field_work_panel.gd:12](../../../ui/field_work_panel.gd#L12) 与 [choices:52](../../../ui/field_work_panel.gd#L52)。战利品 footer 为 HBox，标签没有扩展宽度、旁边又有长按钮，见 [frontier_hub.gd:65](../../../gameplay/frontier/frontier_hub.gd#L65)、[expedition_screen.tscn](../../../gameplay/foundation/ui/expedition_screen.tscn)、[widgets.gd:3](../../../gameplay/foundation/ui/widgets.gd#L3)。确切最小尺寸传播路径仍需编辑器/运行时布局核实。

**最低可行修正 →** 限制作业卡最大宽度与视口边距，长选项用短标题并在独立详情显示全名；footer 标签占剩余宽，窄时上下排列，按钮维持可点击尺寸。溢出内容进入明确的滚动区。

**长期方案 →** 定义共用的浮层宽度、文本与按钮伸缩规则；短标题、消耗、状态、细则各有位置，避免靠一长段话撑尺寸。

**验收标准 →** 1152×648、1280×720以及项目正式支持的最小尺寸中，最长休息选项、长拒绝理由、空列表、4项以上战利品均无越界/单字长列；Tab焦点能到所有按钮，滚动与T/鼠标都可操作。

### P1-04：旧装备详情和统一背包使用不同的可装备条件

**实际现象 →** 首玩在祈坛得到游魂吊坠，旧详情中的“装备”灰色且没有可读原因；转到实际行囊后，同一件装备能够穿上，100HP→85HP。不是物品丢失或必需回镇。[旧详情](screenshots/039-pendant-old-detail-disabled.png)与[实际穿戴](screenshots/040-pendant-inventory-equipped.png)保留该次差异，未额外构造所有状态重现。

**玩家影响 →** 玩家无法判断是没领取、需要回镇、附近危险还是装备不合规；会误学“字段相同但不同页面规则不同”。

**原因假设与核实 →** 高置信度，旧 [show_detail:158](../../../gameplay/exploration/expedition_equipment.gd#L158)直接要求 `is_at_base()`；同文件 [change_reason:182](../../../gameplay/exploration/expedition_equipment.gd#L182)却支持 `field_equipment` 并检查当前动作/附近敌人。确认有两条 UI 校验逻辑，不代表领域层允许非法穿戴。

**最低可行修正 →** 旧详情复用 `change_reason()` 和真实拥有状态；禁用按钮旁显示原因，发现装备后的说明同步改为当前规则。

**长期方案 →** 详情、背包、O页只保留一个“能否穿戴/原因/比较”的查询来源，所有写入仍走现有装备服务和库存事务。

**验收标准 →** 同UID在两个页面可用性一致；安全野外可穿，附近威胁/动作中准确拒绝；失败保留原穿戴和物品，不以只看灰色按钮代替真实点击测试。

### P1-05：非线性探索后的交付承诺与任务解锁不一致

**实际现象 →** B 阶段完成遗钟后，屏幕明确提示“返回镇中可交付遗钟回执”：[完成提示](screenshots/025-core-completed.png)。我回镇后能交名字支线，但“可交付”筛选没有回执主任务；名字交完后[可交付为空](screenshots/034-no-deliverable-main-quest.png)。没有把它描述为整条任务丢失。

**玩家影响 →** 玩家先走墓道也被允许，完成后却收不到刚承诺的回报，难以分辨是交错NPC、缺前置还是存档错误。

**原因假设与核实 →** 高置信度：[回执任务:3409](../../../content/frontier/grayriver.json#L3409)要求四项墓道成果，同时以 `demo.watch.signal` 解锁；[frontier_hub.gd:133](../../../gameplay/frontier/frontier_hub.gd#L133)先过滤未解锁任务，连“全部”也不会展示。最终只读存档确认四项成果齐全、烽堡信号为false、回执未交。

**最低可行修正 →** 选定一条产品规则：允许先完成的调查先交付；或者完成提示明确“回执已保存，取得烽堡信号后可一并提交”，任务页展示待解锁条件。当前自由选路的承诺更适合前者。

**长期方案 →** 把“任务可见、目标已完成、允许交付”分开表达，完成反馈由任务服务查询生成；后续依赖可以控制剧情呈现，不必隐藏已经亲历完成的任务。

**验收标准 →** 用正常新档分别按“烽堡→遗钟”和“遗钟→烽堡”推进，四项成果不丢；所有完成提示与可交付状态一致，回报只发一次。该逆序测试不需要瞬移或强写事实。

### P2-01：首个组合教学的阅读、选材和安全准备负担过于集中

**实际现象 →** 火阵长文同时解释轮盘、槽位、火石、站定、射程、阵充能、凝能差异与新技法；阅读时守林兵实际靠近并致死。初次自己又按R打断了铭刻，随后把阵设在射界不理想的位置。第二次成功的差别主要是知道“先退、等成形、保证射界、留在阵里”。

**玩家影响 →** 失败时要同时猜输入是否接受、准备是否完成、材料是否选对、是否在阵内及是否打中，难从一次反馈学会一条规律。工具停顿放大了暴露时间，因此不把此次死亡当作所有真人的必然结果。

**原因假设与核实 →** 中高置信度：数据的首次说明基本就是完整长文；[grayriver.json:78](../../../content/frontier/grayriver.json#L78)与[发现展示:190](../../../gameplay/exploration/exploration_presenter.gd#L190)支持这一点。未测敌人正常玩家阅读时的实际到达分布。

**最低可行修正 →** 首屏只给“先退西侧→M选5火石阵→站定完成→阵内R”的短步骤，把聚能投射后置到日志；记录/可安全回读点放在首敌明确威胁范围之外。给准备开始、取消、完成、阵外短火花四种不同反馈。

**长期方案 →** 做一段只教一个变量的实战：安全布阵、观察一发远射，再让敌人逼位考验退路。保留世界不暂停，不以全局暂停替代布局和信息设计。

**验收标准 →** 新玩家无需回看攻略即可说明火球为何成功/失败；读初屏并操作不会在无预警下直接接近死亡；主动取消不扣材料，成功布阵明确显示实际源与剩余能力。普通按下施法和可选按住预览都需测。

### P2-02：交互物、地标和设施的视觉层级不足

**实际现象 →** 手册、口粮、多个记录在首玩中都是相近棕包；镇中多张桌子也不容易从远处区分功能。靠近后F标题是可靠的，但我常先猜“这是什么”，再走近读。其间也有明确的工具走过头和树木碰撞，不能全部算视觉问题。

**玩家影响 →** 大地图开放探索容易变成逐包查文字；墓道净化架和下行门的空间关系没在我首玩时形成记忆。

**原因假设 →** 中置信度，实际观感成立；未做美术资产/可访问性审计，不判定具体贴图使用错误。

**最低可行修正 →** 先为知识、补给、入口、作业装置、服务台建立不同轮廓/图标；关键岔路让“可走入口”与道路尽头清楚相连。对已发现设施保留简短标记，文字只补充功能。

**长期方案 →** 用不同区域的结构、色调、风险地形和可回望地标支撑空间记忆；同类功能保持同一视觉语言，不依赖增加常驻文字。

**验收标准 →** 遮去长说明，玩家仍能分辨书、补给和可修装置；从入口读完净化提示后，能指认大致寻找方向；可交互与纯装饰桌台不会连续误认。

### P2-03：生存的实际代价与恢复收益需要更容易看懂

**实际现象 →** 我最初花掉两份饼和两份水做两次三小时休息，后来在菜单/安全区域停留也从半血恢复。快捷吃喝紧接移动会被打断，站定等待才成功。常驻提示说饥饿/缺水/疲惫，主要收益和规则却需要深入页面阅读。

**玩家影响 →** 容易将休息理解为“唯一恢复法”，或反过来发现等待能恢复后完全忽略准备；也容易把中断误认为热键没响应。这是信息与节奏风险，未证明经济失衡。

**原因假设与核实 →** 高置信度的规则、低至中置信度的平衡判断：[survival_needs.gd:53](../../../gameplay/exploration/survival/survival_needs.gd#L53)营地需求消耗为野外四分之一；[survival_service.gd:93](../../../gameplay/exploration/survival/survival_service.gd#L93)说明饥渴减少回复、疲劳增加准备时间，低需求不会直接扣血。保留不封锁返程是合理取舍。

**最低可行修正 →** 在吃喝/休息按钮旁给“当前缺什么、改善多少、需要站定多久”；中断时短提示“移动打断，未消费”。展示当前自然回复和食品额外回复，避免把所有恢复都归因于刚喝的水。

**长期方案 →** 用正常手动玩家对比“安全等待、吃喝后继续、付物资休息”三种策略的远征收益；先测是否形成支配策略，再调整数值，别直接削回复或增加强制饥饿伤害。

**验收标准 →** 玩家知道低需求的实际惩罚、能预测一份物资的收益；中断不扣物资；不同准备策略至少各有合理场景。不能用工具长时间思考造成的饥渴证明正常玩家补给不足。

## 应保留的设计与需要深化的部分

### 战斗、组合与对策

火阵远射是本次最有说服力的核心：真实材料、准备承诺、空间和持续消耗共同决定效果，成功后能解释“为什么赢”。装备也不是纯数字按钮：刀/护甲取自敌人的实物，吊坠提供施法取舍而降低最大生命。应围绕这些已连通的少数规则做更稳定的敌人与场地互动。

本次没有可靠测到敌人射界、精准格挡、侧绕锁向攻击、重击、闪避窗口、AI材料耗尽后的行为。因此不能写“AI没有对策”或“近战只有站桩”。视觉辅助的简单攻防本来就不能代表熟练玩家。我只观察到用远射与射界能降低风险，而基础近战的伤害很快；下一轮需要正常低延迟操控来验收实际手感。

优先补一个“看见危险→选择准备→观察结果→改策略”的完整遭遇：例如同一场景让水洗毒提供安全走位，火阵提供稳定远射，绕柱近战提供省材料方案；让敌人的迫近/移动破坏原阵位，玩家再决定花料重布还是拿刀收尾。这里应复用已有动作和表面反应，**不再加一个专用组合技按钮**。

### 机关、任务与关卡节奏

B 阶段证明机关有真实层间推进与返程收益，南侧绕毒、柱障和独立下层构成了一次远征的骨架。手动路线使缺技能玩家仍有机会推进，应保留材料与暴露时间的代价。

但目前我实际体验的三个装置，在战斗清理后都趋向“按F等6秒”。提示列出元素序列本身不等于谜题决策，更多同构机关会稀释内容。下一步宜让少数机关改变当前空间：净化后当场产生可走路线/明确水流变化，开封条后出现能回望的路径，遗钟成功的声画/视线反馈连接新出口。净化效果若设计为重进才生效，应当在现场可读地说明这一生命周期；本次已有文字说明，不应未经权衡强改为即时模拟。

主线任务建议由“当前一次远征”的两三项可读目标领起，其余支线渐进展示；开局我首先看到许多0/N任务，较晚才理解巡河长线。路线开放可以保留，任务可见/交付应支持玩家实际发生的逆序探索。

### 制造、交易、采集与物品身份

这几项本次已有实效：加工耗真实材料；晶脉给可用金属；交易把施法资源换成武器；尸体留装备和补给；丢弃再拾回可完成；制作烤饼真实替换谷粮；保存重进保留任务成果。没有观察到免费刷新或丢物，但也没有做同UID喷剂余量/涂层、满容量回滚、摔落背包与多区域落地容器的全面测试，不能宣称库存系统全部通过。

建议先给一份清楚的“这趟带什么”视图：口袋可施放量、背包备用量、当前动作所需来源、食水共用的数量。不要替玩家自动补料或自动更换来源。让同一份晶砂用于火石、机关或出售的机会成本被看见，远比再添五种颜色的材料有价值。

### Godot 架构：本次能核实什么

后验抽查中，`FieldWorkSites` 把现场交互/完成委托给进度服务，`FrontierHub` 主要构建查询视图、提交动作，`GrayriverDefinition` 将数据装配为类型化资源；`change_reason()` 已存在共用条件接口。这些边界有利于局部修正，无需为本报告的问题重写框架。

暴露出的架构问题主要在**表现条件的权威不统一**：同一种前置被通用文案误译、旧装备页复制营地判断、任务完成提示是数据长句却与任务服务的交付条件脱节。应把“当前能做什么、为什么不能、下一步是什么”视作可查询的领域结果，交给各界面一致展示。不是再加一套任务状态、另一个库存汇总或万能事件总线。

这只是与实际问题相关的代码核实，未审计事务回滚、信号生命周期、场景卸载、所有UID和存档迁移，不提供全架构合格结论。

## 两小时 Demo 完成度判断

**已经具备的骨架：** 独立新档与恢复、出发整备、连续野外、多个实际区域/多层遗迹、材料和战利品循环、死亡返程、机关和任务奖励，B 阶段实际走出的捷径能缩短回头路。它有发展成两小时远征 Demo 的基础。

**尚不能验收的部分：** 本次未走通巡河终章，未完成烽堡/泵站/旧监狱，没体验泵站复水与封压的实际后果，也没有完整 NPC 交涉、进阶制造和多种元素对策。源码里有这些定义不等于本次体验成功；不以区域个数乘预计分钟数来凑两小时。

**当前判断：** 内容骨架比“纯战斗样机”完整，但首次玩家从提示到首次组合、从组合到明确远征目标、从逆序探索到可交付成果的链条仍不稳定。建议先让一条代表性路线稳定产生约20–30分钟的完整准备、风险、发现、成果和返程体验，再用正常玩家实测组合三段远征的总长度。20–30分钟是下一轮设计目标，不是本次已经测得的时长。

下一轮时长记录应单独计主动探索、战斗、说明阅读、整备/交易、机关站定、死亡恢复、有效返程、迷路和停留；至少包含几名没有看过内部资料的玩家，记录提示求助次数、首次成功火阵、首项机关成果、第一次任务交付和最终结束时点。离线、工具调用、录像整理不得计入内容时长。通关玩家和未完成玩家都进入结果，避免只统计最快成功路线。

## 分阶段开发路线与验收清单

### 第一阶段：让现有信息可靠（建议1–2个集中工作日，需开发者复估）

范围严格限制在现有提示和界面：修旧窖方位；让封条显示净化前置；统一装备可用性；统一回执交付承诺；修窄窗口布局。

- [ ] 新档由手册→猎营→档案窖的方向与命名准确。
- [ ] 净化前后同门的拒绝理由、材料、操作状态准确切换。
- [ ] 同UID装备在发现详情与背包中可用性一致，拒绝理由可读。
- [ ] 先遗钟后烽堡的玩家得到清楚且真实的交付规则。
- [ ] 最长作业文本、战利品页脚、空列表在最小支持尺寸内可读可点。
- [ ] 保留真实物资、世界持续运行、现场打断与失败不收费规则；相关变更走现有服务，完成匹配回归和原生键鼠验证。

### 第二阶段：做稳首次远征（建议3–5个工作日的设计/实现/验证预算）

以手册→火阵→一次遭遇→实物奖励→首个机关/记录→返镇交付为一条垂直片段。先减少第一屏的信息，建立动作反馈；再改地标与安全阅读位置，不增加动作和材料种类。

- [ ] 新玩家能描述“阵内远射、阵外短火花”，能识别布阵准备被自己打断。
- [ ] 一次失败后能从游戏信息中自主改变位置、准备或装备，而非只重复同一路径。
- [ ] 至少两个合理策略能处理代表遭遇，均付真实代价；用正常操控测，不用本次视觉宏证明战斗难度。
- [ ] 获得奖励后能发现回镇/继续探索的取舍，首次交付有明确完成反馈。
- [ ] 一份材料在战斗、制造/机关、出售之间的机会成本可理解。

### 第三阶段：深化差异并验收全程（建议1–2周，取决于现有实现复用）

不以铺更多房间为目标。先让三个远征各有一种主要空间/资源决策，验证泵站不可兼得后果；再测正常新档全程、逆序路线和持久性。

- [ ] 净化、封条、校准等装置至少在布局变化、风险或资源策略上产生差别，而非全部变成长按/等待。
- [ ] 玩家在作泵站决定前能理解复水/封压各失去什么；决定后在东岸取水、炉灶、维护箱/捷径看到实际后果。
- [ ] 完整巡河终章由正常新档真实输入到达；退出重进后机关、敌人实物余量和任务奖励不重置、不重复。
- [ ] 双向元素组合、物品容量、喷剂/涂层UID等按变更范围做有意义的失败边界测试，不靠单一路线截图宣称全部通过。
- [ ] 由独立玩家测得主动内容、阅读、整备、返程与迷路时间分布，再决定是否满足约两小时定位；不以新增数量补足未测时间。
