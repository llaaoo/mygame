# 项目审查与本轮优化

2026-11-10；基于`bdfca5316ef67b4f3f026654802e480a0da0ae30`，延续Godot场景组合、不可变Resource与角色/Session服务所有权。没有更换引擎、复制领域状态或为了使用插件重写玩法。

## 审查结论与落地

| 范围 | 当前判断 | 本轮处理 |
| --- | --- | --- |
| 输入与世界交互 | 请求时重验目标是正确边界；空焦点未缓存导致标签重复扫描全场 | 空结果也按物理帧、玩家位置与区域generation复用；删除/离树焦点失效。真实F与鼠标请求继续强制查找并重验 |
| 库存、装备、交易 | InventoryService作为唯一写入边界符合所见即所得；UI只需要格数时不该复制全部实例 | 增加`occupied_slots`只读查询，背包每帧概览不再通过完整物品快照计数；不引入第二份数量缓存 |
| 成长与实时界面 | ActorProgression与原成长所有者保留；隐藏界面不需要持续刷新 | 成长页仅在实际可见时周期刷新；世界计时、受击和AI继续运行 |
| 法术与物资 | CastPlan、真实来源和提交重验应保留 | 没有给施法计划加跨帧通用缓存，避免来源/知识/法阵/UID失效后的错误承诺；规则与材料预算不变 |
| AI与导航 | State Charts已用于敌人，角色动作仍走共同执行器 | 保留既有状态机与战术服务；只读样本未显示导航查询为本次热点，没有另加LimboAI控制同一角色 |
| 动画与画面 | 表现与领域提交分离的方向正确；云端软件渲染仍慢 | 使用MCP采样、截图和真实输入定位，未用关AI、停世界或减少实物显示换性能；后续仍需目标硬件Profiler |
| NPC、任务与法律 | Conversation/Relation/Progress/Law各有所有者 | 保留服务边界和有限实物交易，不把Dialogue Manager扩展成第二份任务状态 |
| 存档与区域生命周期 | 原模块化保存与generation边界继续有效 | 增加正式入口之外的内存检查场景，F5/F9只接检查场景的MemorySaveRepository；焦点缓存不跨区复用 |
| 开发工具 | MCP的成功/错误与新旧消息判定不可靠 | 修正命名类型审查、编辑器与运行进程差异、同步脚本错误/打印捕获、回复新鲜度和引擎版本标识；新增可复用CLI |
| 既有大型/兼容代码 | 旧Room/RunManager入口仍有独立回归用途 | 不把文件长当作删除理由；本轮删除MCP里重复的匿名编译与猜测错误位置逻辑，复用实际Godot诊断 |

MCP分别审查`core/entities/gameplay/ui/world/demos`共409个自有脚本，结果没有编译错误、缺失资源或目录内循环引用。这个按目录的审查不是跨全仓依赖图证明，也没有把未启用第三方插件当成当前游戏能力；资源目录、地图和运行行为继续由完整回归覆盖。

## 实测与限制

在相同内存场景、24名正常AI角色、95个交互物、没有附近焦点时，5轮查询（每轮按交互物数调用焦点查询）由15024微秒降为413微秒，约36倍。该结果是受控查询成本，不是整机FPS结论；`has_focus=false`和唯一`sample_id`均记录在原始回复中。新增输入检查还验证一次空样本内200次查询只扫描一次，新增目标可被强制查询与真实F发现，删除/移动使旧焦点失效。

修正后的新鲜MCP软件渲染样本仍约6 FPS、147ms帧时间，物理帧约5.8ms。早期MCP曾把启动/旧快照标为成功，这些FPS数据不作为对照基线。画面性能还没有达到验收目标；当前Xorg/Mesa llvmpipe不能替代目标设备。下一步应在目标硬件用Godot Profiler与渲染分析区分绘制提交、Shader、灯光和UI成本，再决定分块/批处理策略，不能从一个云端样本猜改游戏规则。

MCP实际发送I、P、F5/F9并截图：背包和成长页可开关、世界时钟继续推进、检查场景的仓库为MemorySaveRepository。这是受控操作验证，没有声称自然通关、首玩路线或2小时内容验收。

## 插件的使用边界

ChatGPT侧实际使用Plugin Management核实连接、GitHub读取Godot 4.6官方API与交付。Figma、Context7、Superpowers仍未连接，未冒称调用；Game Studio当前可见技能偏浏览器游戏，不据此改变原生Godot栈。

Godot侧实际使用MCP的项目/脚本审查、运行探针、输入与截图，以及GUT领域检查。现有State Charts和地图制作继续沿用；未启用的Phantom Camera、Importality和AI供应商插件保留按需接入，没有新增付费API或恢复Actions。[MCP工作流](GODOT_MCP_WORKFLOW.md)记录启动、schema发现、隔离、等待和退出码；[验证报告](playtests/mcp-optimization/REPORT.md)记录归档来源、实际覆盖和限制。
