# 系统完整性与内容扩展

2026-11-08，北京时间。基线18d1363。优先明确权威、生命周期与内容接入，暂不调整战斗数值或动画。

1. 食品/饮水/茶的计时与属性由同一Buff实例拥有，SurvivalNeeds只持有长期需求，旧计时字段作为迁移/查询投影。死亡先结算状态清理，再计算恢复生命；正常跨区、休息、读档不续满。保留无场景的旧需求模型适配。
2. 整修铺加入按配方、真实库存和游戏时钟排产。订单不预扣原料、不预占货品，完成时原子加工；缺料/满库保持阻塞，补料后继续。停单无扣费，无追补离线产量，不从模板刷新货品或河谷币。保存、F9、休息和新旅程遵循同一状态。
3. 武技目录、训练师提供的课程、知识前置/探索条件/互斥选择用Resource表达。旧武技ID和存档兼容；条件只限制学习，不删除已学能力。重复授课、技能书与训练师统一校验，不允许付钱后才发现不可学。
4. 内容验证器检查重复ID、引用、无效配方、循环前置及互斥；界面显示真实条件、排产状态与阻塞原因。新增少量代表配置贯通原有流程，不批量增加地图/技能。
5. 分层验证状态迁移与死亡、真实材料守恒与加工阻塞、条件学习/失败不扣费、鼠标交互及连续保存重进；从干净代码提交归档全量回归，按AGENTS创建PR合并，Actions保持停用。

架构继续遵循Godot4.6官方场景组织与Node替代类型建议：入口装配，Resource定义不可变，RefCounted持有运行态，UI提交领域请求；不增加Autoload、通用规则语言或第二份库存权威。
