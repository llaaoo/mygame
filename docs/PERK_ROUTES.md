# 灰河谷当前Perk路线

2026-11-14（上海）。以真实装备、材料与基础操作为中心；已经进入运行时，不是原独立法术树的扩充提案。每升一级仍只有1点全局Perk预算，属性点、技能知识、配方和觉醒资格各归原系统。

## 六条路线

每条7个可学习节点。原有四条生活/武器路线的20个有效节点继续保留，新增8个末段节点；两条法术路线提供14个节点，共42个当前节点。全部来自只读Resource，UI查询与实际学习共用条件。

| 路线 | 成长方向与取舍 |
|---|---|
| 武器与武技 | 原体力、节能、武技、反击与破势节点；增加涂层保养、元素收招。先准备实际附魔，再用手动连招释放，未觉醒者也能走这条路线。 |
| 防御与机动 | 原格挡、闪避、回气、冲刺与储备；增加行进调息、稳盾卸压。格挡回气仍等待真实消耗延迟，不自动防御或反击。 |
| 制造与整修 | 原工具、箭簇、拆解、整修与工序；增加炼剂分装、涂附工序。强化与拆解仍操作具体实物，配方和原料各自取得。 |
| 野外与补给 | 原需求、负重、草药、休息与食品；增加耐途补给、猎材精取。专业取材另需剥皮及具体部位的技能、工具；Perk不是课程。 |
| 术式与反应 | 术式调息 → 元素研习／投射节律 → 介质防护／移行研习 → 反应专注／量能施术。主动施法需要觉醒，投射与移行另需对应操作知识。 |
| 铭阵与调谐 | 稳固铭阵 → 阵能整流／调谐稳持 → 阵纹续存／调谐节能 → 塑形维系／回响整持。各分支要求原操作知识，不能点出Perk就凭空布阵、取得恩赐或召唤物资。 |

节点按角色2/3/5/7级和分支实践1/3/6/8级分段；基础属性与前置以选中节点详情为准。顶层节点只需角色2级、1点预算。每个节点花1点，不能同阶段全点；新末段需要长期专精与跨系统准备。

## 实际联动

- 武器：涂层保养延长25%，制造侧涂附工序再加15%，一份60秒抹布的新涂层可成为84秒；它仍属于原武器UID。元素收招将基础18点释放伤害改为21点，近身附魔释放与行进波共用查询，原普通附魔命中不重复受益，实际伤害仍经过目标防御与抗性。
- 法阵：稳固铭阵让基础凝能阵120秒成为144秒；阵能整流让每次40秒成为34秒。CastPlan提供同一预算给预览和布置，持续时间照常流逝、触发仍扣余能。学习不延长已经存在的阵；材料与法力不因降低阵能消耗而退款。
- 炼金：明确标记为炼金的10种抹布、投瓶与喷剂配方，每批额外1份，最多翻倍；完整付原料并检查全部空间。这类带使用配置的成品沿用不可逆向回收规则，普通材料仍按原损耗回收；目录拒绝给可回收原材或弹药叠加炼金产出，防止无损刷原料/熟练度。NPC代加工不读取玩家的手工Perk。
- 取材：猎材精取对真实部位的每类产物加1。现场提示、容量预检、实际转化和成功事实共用InventoryService.anatomy_outputs。未学会该部位技艺、工具丢失、墙体遮挡或放不下时保留原部位；同UID只能消费一次。
- 补给：耐途补给和原食品回气节点只在实际食物有效期间加回复，休息仍走游戏小时，负重承受不增加背包格数。

## 实践、知识与界面

P打开六条路线；先选节点看效果、条件和缺少原因，再确认学习。世界与AI不暂停。节点和详情分别滚动，锁定节点仍能查看，鼠标与Tab可达；学习不打开另一个法术编组界面。

旧熟练度记录保留，路线读取相关记录的最高等级与进度，而不是合并XP或复制等级。术式读取原毁灭/幻术实践；铭阵读取相关铭阵/调谐/塑形历史记录。新操作施放实践按实际操作归路。该兼容投影不发奖励，角色经验与全局点数仍只按原成功实践和等级规则结算。

特定节点通过ActorContext.learning_query读取原知识所有者；不另建已学知识表。获得知识后界面原位更新拒绝原因。基础属性满足永久学习条件，临时装备/增益不能代替基础属性；资格、点数与死亡状态也在真正提交时检查。

## 旧档与接入边界

20个旧法术节点保留原ID、效果、前置和成本，标记legacy_only。已学节点在“既有传承”查看，不再出现在新学习树，不自动退款、删技能、重置资源或重复发历史信用。未学旧节点不能购买。四条原日常路线保留其20个ID；存档schema2及原9个存储编号不变。

新增节点使用SkillPerkData，可声明requires_awakening与required_knowledge。SkillTreeData.practice_schools只描述读取来源，不拥有另一份熟练度。目录校验拒绝未知效果/知识、环、缺前置、主动节点依赖退休节点、主动节点重叠和无费用自动施法。

| 效果 | 实际执行消费者 |
|---|---|
| field.duration / field.use_cost | CastPlan.field_budget → ConditionalCastController布置 → FireSigil原消费 |
| coating.duration | ItemActionController实际涂附成功时写InventoryService的武器属性 |
| enchantment.release_damage | WeaponEnchantment.release_value，近战释放、实物箭与EnchantmentWave共读 |
| craft.alchemy | CastingSupplies.craft_output，预览与实际库存事务 |
| harvest.anatomy | InventoryService.anatomy_outputs/process_anatomy、CorpseHarvesting现场提示 |
| cooldown.project / cooldown.step | 原CastCostPolicy，按实际基础操作ID结算 |
| 原体力/负重/食品/制造/状态/召唤键 | 原ActorProgression、动作控制器、库存、需求与SkillExecutor |

新增修饰必须先接实际消费者，再登记允许键；不能只增加一条说明。法阵、涂层和取材不成为新的存档模块；它们仍归原来源、区域与实物生命周期。

## 本轮验证策略

按用户要求默认定向验证：内容/GUT、成长条件与实际保存重进、附魔、专业取材、基础操作，以及真实成长页操作与小窗口。提交归档只验证首次导入和相关用例；不因为改了多个文件就运行全量，也不为证据提交重复测试。未运行的全项目用例不写成通过，结果与平台单独归档。
