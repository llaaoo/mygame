# 状态、生产与知识的扩展基座

2026-11-08，北京时间。起点18d1363，实施边界见[计划](SYSTEM_EXTENSIBILITY_PLAN.md)。本轮不调整武器/法术伤害、材料价格、敌人预算或动画，重点是系统接入、生命周期和内容定义。

## 一个状态时钟

食品、饮水与茶的实时剩余时间、属性和恢复加成都由`BuffManager`的同一状态实例提供。`SurvivalNeeds`仍持有饱食/饮水/疲劳与采集再生；原食品字段是查询/旧档迁移投影，绑定角色后不再独立递减。独立需求模型保留旧API作兼容测试适配。

| 生命周期 | 当前规则 |
|---|---|
| 普通跨区、返镇、F9与重进 | 保留实际个人效果与周期相位；不续满，不重新触发施加/清毒 |
| 休息 | 推进同一游戏时间和状态，不以移动物理的小时delta替代 |
| 死亡 | 在角色发布死亡/计算恢复生命之前，清理默认不保留的定时状态、元素积累和控制恢复；装备永久贡献保留 |
| 死亡存档 | 保存当前死亡角色快照，不能继续沿用上次活着时的食品/异常/生命状态；重进按原半血半蓝规则返回镇中 |
| 法阵、区域能量与准备 | 仍为区域/动作瞬态，死亡或离区清理 |
| 武器涂层/喷剂 | 仍属于具体UID的实例属性，按原绝对期限/剂量处理；不转存为角色Buff |
| 冷却 | 保留实际冷却，死亡不额外清零；离线不推进 |

Buff可显式配置`survives_death`，默认定时状态不跨死亡。食品目录引用真实状态定义，同组替换；清除/到期会同步影响属性、恢复、补给计时与保存。死亡后“食物计时清零而耐力仍+2”的已复现边界已由同一时钟解决。

存档版本9：旧v8中食品的两份计时按实际需求剩余时间、且不延长已有状态迁移；不存在的食品不保留幽灵属性。旧饮水/茶剩余时间转换为状态，不回放喝茶解毒。新记录带`provision_schema`，后续F9/重进直接恢复权威效果。

## 有来源的持续供货

整修铺 → “店内排产”可安排箭、火石、石肤药剂的现有配方。真实配方输入、完整产出空间与时间共同约束生产；输入不足或库容不足都不会部分扣料。订单保存截止时间、剩余批数与阻塞状态，没有第二份库存。

玩家供货进入店家实际容器，生产的成品也进入该容器，购买时付款回到店家。工期会随正常游玩及小时休息推进，离线不推进；停止不扣原料，完成批次不重复领取。UI持续读取进度/库存并原位更新控件，世界保持运行。没有重置模板、免费补货、造币或给玩家发NPC生产经验。

## 可配置的成长与内容边界

武技ID、前置链和互斥专精由`MartialCatalog/MartialTechnique`定义；课程费用和世界条件由`LearningOffer/TrainingCatalog`定义。K编组、书、知识保存、物理执行和附魔继续复用原系统。课程付款前重验，失败回滚；旧知识保留。

本轮不批量增加新技能/专精内容。现有横扫课程的实物战杖条件展示世界条件的真实接入；前置链、互斥及书的共同限制通过独立领域验证。后续作者可以增加资源定义和学习来源，新的动作语义仍需扩展代码。[内容接入指南](CONTENT_AUTHORING.md)列出具体目录、字段、登记、验证及兼容要求。

验证器现在联查食品身份/互斥槽、武技重复ID/循环/不可满足前置、课程引用/费用/条件、生产原料/产出和店家初始库存。纯定义使用Resource，生产与学习服务使用RefCounted，场景入口装配服务；没有增加Autoload、ECS或通用脚本语言。
