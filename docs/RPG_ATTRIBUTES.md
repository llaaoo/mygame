# 属性系统：成长、环境耐受与任务处理方式

2026-11-05。在四项现有属性与存档上扩展用途，承接[试玩问题迭代](./PLAYTEST_FIXES.md)。本批实现属性基础，不把完整生存模拟或通用任务编辑器当作已完成内容。

## 当前规则

| 属性 | 已有影响 | 本批扩展 |
|---|---|---|
| 力量 | 每点增加2基础物理加成，经探索近战倍率与现有Buff计算 | 可用于任务的搬运／检修方式；训练页展示下一点的基础近战变化 |
| 智力 | 每点增加2魔法加成、3法力上限 | 可用于基于记录的任务推演；训练页并列展示魔法与法力变化 |
| 敏捷 | 每点增加3基础移动速度 | 超过10后，每点缩短1.5%条件施法准备时间，属性部分最多缩短30% |
| 耐力 | 每点增加5生命上限 | 超过10后，每点降低2%持续、环境与陷阱伤害，最多40%；保留对应状态和环境风险 |

初始四项10时，100 HP／60 MP、现有费用与准备时间保持。探索基础近战18伤来自上一批校准；投入力量仍正常成长，例如力量14的基础近战为23伤。智力14时魔法加成28、基础法力上限72；敏捷14的属性准备倍率0.94；耐力14的基础生命上限120、危险伤害倍率0.92。

敏捷的准备修正与装备相乘。例如敏捷14配节律护手，准备倍率为`0.94 × 0.80`。它不直接缩短技能冷却，也不把瞬发或持续引导改成另一套施法逻辑。

耐力保护的是带`dot / environment / trap`交付标签的伤害，涵盖地面状态的周期伤害和现有尖刺陷阱；普通近战、范围或投射物不会仅因带有火、水、雷、毒元素就获得这项减伤。使用原有命中上下文与伤害入口，附加伤害复用命中前快照，避免重复减免。伤害仍按现有整数规则取整，小额伤害的变化可能暂时不明显。

## 同一个有效属性来源

成长链：经验与委托获得属性点 → 营地分配基础属性 → 装备与Buff影响有效主属性 → 计算派生数值、施法准备和任务条件。

- `StatsComponent.primary_values / effective_stat`查询当前有效主属性；装备继续通过已有Buff负载贡献，不新增装备属性系统。
- `derived_values(overrides)`只投影下一点的基础派生结果，不改动角色、Buff或资源。训练页区分实际当前结果与下一点的基础变化，直接修正生命、伤害的装备效果另计。
- `meets_requirements`对多个属性要求作AND判断；未知属性、非法阈值不视为满足。
- 准备计划记录有效主属性快照。准备期间属性或相应Buff发生变化，会重新校验并取消旧计划，保持材料、法力和条件不泄漏。
- HUD显示有效属性并跟随Buff／装备变化刷新。训练先扣点再通知观察者，非法属性不会扣点。

任务条件在实际提交时重新检查。临时Buff或装备可以帮助达标；已经真实完成并保存的任务事实不会因为Buff到期而被撤销。

## 狱中复核的三种处理方式

原有方式保留，属性构筑可以选择另一套凭据。奖励均为同一份1属性点：

| 方式 | 需要的属性 | 探索凭据 |
|---|---|---|
| 完整现场报告 | 无额外属性门槛 | 三份实地观察＋三个机关完成标记 |
| 记录推演 | 有效智力14 | 三份观察＋清理档案室、回廊、机房 |
| 重载检修 | 有效力量14 | 三个机关＋清理档案室、回廊、机房 |

推演不会替玩家开启未解机关或检修通路，也不会虚构已验证的元素反应。检修不会替玩家阅读遗漏记录。任何方式交付后，其余方式全部禁用；旧存档已交付的任务保持已交付，不补发奖励。

完成方式写入已有`choices["quest.field_research"]`，报告保存在原日志，复用原一次性领取标记。属性、装备、知识和材料继续使用原存档。未包含新选择字段的旧进度采用现有默认行为。

## 继续完善的方向

下一阶段应先扩展具体用途与场景，再评估是否需要新主属性：

1. **战斗成长**：用相同等级和属性点预算比较力量近战、智力法术、敏捷准备和耐力承压；记录准备次数、资源、受伤与成功率，再调整成长曲线。保留普通施法和不同恩赐处理方式的价值。
2. **生存用途**：当前已接入危险耐受。负重、体力消耗、休息恢复、食物和疾病应依托真实资源循环逐项加入；需要先确定补给来源、失败代价与恢复手段，不能只在属性面板增加空数值。
3. **探索交互**：通过同一有效属性查询给搬动障碍、维护设施和风险通行提供可选处理方式；必要通路仍需有基础工具路线。已经完成的机关不因属性下降而重新锁定。
4. **任务与世界反馈**：复用本批的具名处理方式，逐步让不同凭据和属性改变提交途径、耗时、成本或后续帮助；每条方式必须有可观察结果。已读知识、关系与世界事实保持各自含义，不被某项属性直接替代。
5. **成长可读性**：在有足够构筑样本后，再设计营地重分配、软上限和更多装备属性。任务页面继续显示有效值、阈值、缺少的凭据与完成记录。

以上后续方向尚未实装；本批没有增加饥饿、温度、负重或新的体力资源，也没有增加主属性、章节装备或强制属性门槛。
