当前为11个基础动作、24条法术组合规则、10处可选机关、7种材料/7项制造配方，以及4件固定探索装备。完整规则见[技能、Buff与装备迭代](./SPELL_BUFF_EQUIPMENT_ITERATION.md)。

- Shift＋火花/震荡/凝神/水引各消费1层，得到魂焰矢、魂霜震荡、先祖护佑、净魂；普通施法保留。优先级仍为护盾爆破、回响、魂术；不同作用域的法阵相容结果共同结算。

- 四件装备使用已有EquipmentManager和Inventory，固定来源、同槽替换、营地整备、O详情与前后对比。I背包遵守同一营地限制。所属/已装备均持久化，旧存档补领新增固定奖励，不重复生成。
- Buff栏按实例复用行，显示层数/容量、时间、类别、来源与用途；蕴魂在角色周围显示魂点。法阵预览与真实范围、合法性一致。

## 模块边界

| 模块 | 职责 |
|---|---|
| `ExplorationRegionData`、`content/exploration/*.tres` | 区域名字、描述、遭遇、发现、选择事件和出口；为交互点预留障碍净空 |
| `ExplorationQuestData`、`content/exploration/quests/*.tres` | 委托目标、进度计算、完成条件与属性点奖励 |
| `content/exploration/chapter.tres` | 运行与内容校验共享的24法术组合规则注册表 |
| `CastingMaterialData`、`CastingSupplies`、`CastingWorkshop` | 材料适配与运行时修正、库存/加工/消耗计划、M配置与营地工作台 |
| `SpellWorldObject`、`surface_overlay.gd` | 消费真实命中事件的顺序机关；显示实际模拟地面 |
| `MVPGame`、`RegionSession` | 场景编排、共享区域生命周期、遭遇完成与失败恢复 |
| `ExplorationProgressService`、`ExplorationPresenter`、`ExplorationRegionBuilder` | 进度与领域命令、展示、区域节点装配 |
| `CraftingRecipe`、`content/crafting/` | 制造配方，库存原料转为库存成品，与法术组合规则分开 |
| `PrisonArena` | 复用旧监狱房间的地面、墙与障碍表现；不包含奖励和战斗流程 |
| `ExplorationProgress` | 已学动作/法术组合规则、领取记录、区域里程碑、日志与角色持久状态 |
| `ExpeditionUI`、`ExplorationInteractable` | 介绍、日志、暂停、死亡/完成界面与 E 交互 |
| `SpellCombinationResolver.resolve_components` | 分作用域匹配法阵与施法者状态，合并相容结果，筛选互斥增益；不扣资源 |
| `BoonSpellModifier`、`Buff` | 按适配标签计划持续增益与显式消费形态，记录Buff版本和一次性额外成本 |
| `SkillExecutionBatch`、`CastContext` | 暂存实例/Buff/施法事件，全部接受才激活；传递共同动作来源 |
| `BuffManager`、`HealthComponent`、`CombatExecutor` | 准备状态版本与回滚、实际减伤；同次命中反应与主伤害结算；共同动作效果使用来源标识，独立动作保留无敌约束 |
| 现有 SkillManager、SkillExecutor、CombatExecutor | 装备动作、执行结果、伤害与事件；不新增平行伤害通路 |

增加已有行为类型的新法术组合规则可以添加资源并登记到 `content/exploration/chapter.tres`，再在发现配置中授予；不需要为每个法术组合规则复制控制器。新的行为原型或新条件类型仍需要有边界的代码扩展，不能保证任意效果完全无代码制作。

## 进度语义

新游戏只掌握火花和基本近战/闪避。目录中的旧 30 法术保留为资源，但探索入口通过 `known_actions` 限制装备和释放。技能记录授予动作及法术组合规则，同时记录日志；重复阅读不重复发奖。

`SaveManager` 的原有扩展 section 保存本章进度，没有另建一套 JSON 进度文件。MVP 恢复自己的 section 并进入营地，不恢复旧 RPG 的任意战斗快照。版本号统一为 3；临时文件完成后替换目标并备份旧文件。

火/霜/雷法阵、回响印记、共鸣护盾、持续恢复、准备、附魔类临时状态、投射物与地面持续效果在区域切换时清理。清场里程碑和稳定 ID 的破坏物状态保留。关隘清理后营地出现捷径。所有交互和 UI 仍使用原有输入与暂停语义。发现新知识不重新编排已学动作和左右手；新动作优先使用默认空槽，若被占用则寻找其他空槽，全部占满时可在K面板自行编组。F9也恢复保存的编组。

旧升级弹窗、旧 HUD 死亡重开和调试装备赠送在 MVP 入口中隔离，避免抢占新流程。旧房间测试模式保留原行为。

统一入口自动隔离每项检查的数据、配置与缓存目录，首次缺少导入缓存时使用recovery mode导入：

```bash
python3 tools/run_tests.py
python3 tools/run_tests.py --suite quick
python3 tools/run_tests.py --tests content content_contracts region_lifecycle
```

流程推进使用 CombatExecutor 造成测试伤害触发真实死亡，不直接清空敌人列表来伪造清场；组合部分单独使用真实物理目标验证。该测试不等于人工完成整章的难度和手感评估。

`test_exploration_content.gd` 验证两处新增支区、清场前置、救人与营地人物变化、凝神基础效果和三个新增组合、范围命中/减速、Buff互斥/暂停/过期/成长/跨区清理、水路两种效果（含真实Boss火伤减免）、一次性委托奖励、旧进度默认值、磁盘重开和重置遭遇。它也使用真实交互、物理目标与CombatExecutor。

`test_spell_materials.gd` 验证材料获取/加工/配置与保存、三种雷阵法术组合规则、真实工具命中、材料中断与不足、强化投射物/范围、角色与地面联动、顺序机关及一次性奖励。每个流程测试需独立的新数据目录。

## 仍需试玩与后续迭代

- 当前验证以无界面运行、物理交互与流程测试为主；没有共享桌面下的人工画面/手柄/整章平衡验收。

- 背景主要复用监狱几何与现有精灵，剧情、美术演出、音效和音乐尚未按成品打磨。

- 固定材料来源当前有限，没有随休整刷新；本轮数值需通过整章试玩校准，避免资源过剩或高级法术缺料。
- 极端存档损坏/未来版本迁移、复杂模态窗口嵌套和更多行为条件还需要后续专项验证。
