# 物品图像、穿戴预览与界面语气

物品列表、物品检视大图、角色穿戴外观是三个显示用途，共用物品与装备定义，不另建预览库存或外观所有权。

| 用途 | 来源 | 规则 |
|---|---|---|
| 列表/快捷栏小图 | `ItemData.icon`、既有图标目录 | 小尺寸辨识，不因加入插画改变 |
| 行囊检视大图 | `ItemData.illustration_path` | 可选；未配置时沿用当前物品图形，不显示“占位/待实现”标签 |
| 角色穿戴外观 | 实际装备UID、`EquipmentData.world_shape/world_color`、角色动画profile | 复用世界里的`ActorEquipmentVisual`和角色rig；换装、卸下、放下背包与涂层按原状态刷新 |

## 添加插画

在物品或装备`.tres`的Inspector中设置`illustration_path`，或添加：

```ini
illustration_path = "res://content/art/items/your_item.webp"
```

这是示例路径，实际文件必须随项目提交，允许商业使用并登记出处/许可。支持PNG、WebP、JPEG和SVG。建议单品插画约512–1024像素，透明边缘干净、轮廓符合该物品的世界外观；背景留给界面，避免把名称和属性烘进图片。

目录只持有路径，选中物品后才加载大图。界面保留当前选中图片，不让整个物品目录提前持有所有大插画。`ItemArtView`按比例适配区域，不裁物体，也不拉伸比例；切换物品会清除旧图像引用。小图仍有独立用途。无插画时使用已有图形，不宣称已经绘制了所有物品插画。

`ItemData.illustration_error()`与物品/探索内容校验检查本地资源路径和支持格式。坏路径是作者诊断，不放到正常检视界面。物品实例仍只保存UID、数量与实例属性；添加插画不修改存档格式，不把资源或Node写入旅程快照。

## 穿戴外观

插画不会自动成为人物身上的装备图层。新增装备外观仍登记现有`world_shape/world_color`或扩展[角色动画基座](ACTOR_ANIMATION_SYSTEM.md)的共享表现资源。行囊预览复用这些资源、实际UID与当前涂层；不临时换上所选物品，不画玩家没有的装备。只有玩家真的穿戴后，人物展示才更新。

当前采用已有像素角色与装备渲染，面向正面的闲置展示；没有声称已完成所有装备的独立穿戴美术、3D模型或360°检视。后续替换美术应同时核对世界角色、行囊和遗骸，避免各有一套外观。

## 信息与沉浸

常规管理页用当前地点、时刻、物品与人物信息建立上下文，去掉反复出现的“世界继续运行”“只是查看/不消费”等保证性说明。快捷帮助按悬停、选中或展开需求出现；条件、费用、来源失效和当前危险仍必须可见。

世界模拟、AI与计时规则没有改变。受击时的简短警告来自真实伤害事件，Esc仍能收起界面。绑定确认/危险消息占固定区域，不通过增删整行让正在点击的主操作移动。休息仍区分准备秒数与旅途小时，界面不把它称为“游戏小时”。
