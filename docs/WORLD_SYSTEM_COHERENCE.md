# 世界系统衔接与扩展规则

2026-11-10（上海）。本轮处理全项目审查中的生产者生命周期、成长展示、多人物服务和人物线索问题，并深化人情追踪与镇民自保。沿用地图、敌人、配方投入、课程费用和角色数值。

## 有所有者的生产与服务

`ProductionService.producer_reason`由Session注入，只读查询持久死亡记录与当前角色的生命状态。正常排产、恢复和每个批次提交都检查资格；角色死亡时取消其全部未完成订单，不消费或退还未交付原料，已经完成的实物保留。原料/产出仍归InventoryService，不能由UI或排产另存一份数量。

特别覆盖库存通知中的重入：首批已提交后，观察者让生产者死亡，该批实物留在遗骸，后续批次不继续加工，其他订单也终止。完工说明检查实际生命状态，不会在死者完工后继续邀请玩家到店购买。

旧快照若同时保存死者和其未完成订单，先恢复死亡记录，再静默清理订单；不制造库存、退款或完成事实。离区卸载不代表死亡，活着的生产者仍可按原游戏小时工期生产。本轮保留原排程对夜间/休息的计时语义，交易与授课仍受当值限制，不新增工时或配方数值。

`NpcProfile.market`与原`training`显式引用该人物自己的商店或课程。`GrayriverResidents.adapter_for(actor_id)`装配相应服务，交易、买回、课程付款、排产筛选和标题均使用该所有者。原萨芙/训练师门面继续作为旧入口适配，第二位人物不会回退到第一位的库存或课程。没有商店/课程配置的服务会被校验拒绝；初始化和人物挂载幂等，已有库存与死亡记录不会重新灌入模板。

## 一份有效体力回复与稳定的成长页

`ActorProgression.stamina_values`是只读共同投影，返回上限、派生基础回复、需求倍率、食物/装备/Perk加成与当前配置回复，同时提供延迟/格挡条件。Stamina配置与成长页读取这一份计算结果。提高上限不补满当前体力，回复仍受原消耗延迟、格挡、资源上限等执行规则约束。

标准10耐力的基础回复为10/秒；缺水变为3.5，另有严重疲劳时为1.75。P页并列显示当前配置回复与基础值，需求、装备和食品变化能实时更新，不把基础值当作当前效果。属性加点的下一点说明明确展示基础派生变化。

升级、实践经验、临时属性变化和实时回复只更新已有标签与按钮；不清除选中节点、滚动容器或焦点。仅主动切换属性/分支时重建对应布局；控件条件按小型状态签名更新，避免每0.2秒复制完整精通快照或重建全部样式。

## 线索、任务目标与真实来源

NPC话题的`navigation_hints`复用原`ExplorationNavigationHint`。笔记和人物从同一`ExplorationContentCatalog.navigation_text`生成地点、方位及入口/阻塞说明；人物说明以其工作点为清晰参照。J回看人物记录也重新解析当前地点定义，不把旧方位固定在保存文本里。听到线索不获得技能、配方、发现或地图迷雾。

社会目录的跨内容校验检查地区、前置事实/正式任务、导航引用、服务所有者、课程配置和日程缺口/重叠。章节适配器显式提供野外交涉等额外事实；通用目录不依赖灰河谷类名。新的额外事实必须登记，不能靠任意字符串绕过检查。

人情与正式委托继续分别持有自己的完成权威，但共用原`tracked_quest`与Guidance目标查询。J“追踪这个人情”后：

- 缺少物资时显示缺少数量；只建议已经知道、前置满足且未耗尽的真实采集点。找不到已知来源时提示查看已学配方或继续寻找，不透视新地点。
- 物资齐备时转为返回原委托人；夜间、敌对、属性/前置不足或对方缺报酬时说明实际阻塞，不把材料齐备等同于一定可领奖。
- 目标读取活着人物的实际位置；离区时按已知人物日程投影工作/休息位置。交付仍需F交谈并提交原库存事务，追踪不自动消费或领奖。
- 委托人死亡从真实死亡记录推导“无法继续”，不保存第二份失败状态，不继续给出交付箭头；已完成委托不再形成活动目标。旧正式任务追踪ID保持原含义。

## 镇民的自保与测量

`NpcProfile.ThreatResponse`区分RETREAT与DEFEND。萨芙和艾妲受到玩家敌对行为后优先选择导航网格允许的远离路线，移动仍走共同Action与物理碰撞，不能穿墙或传送；训练师保留共同近战防卫。每次敌对反应只发布一次事实，不逐帧刷日志。既有敌人战术AI与野外交涉规则沿用；本轮未增加犯罪目击、司法或同伴系统。

新增输入专项记录帧间隔分位数、最高节点数和引擎进程时间，作为云端软件渲染场景的观察样本，不是目标设备帧率承诺。`first30_probe`补充只读成长、个人追踪和NPC实物/货币账户快照，供默认预算远征与重进核对，不能借探针授予物资或世界成果。

验证与覆盖边界见[衔接验证](WORLD_SYSTEM_COHERENCE_VALIDATION.md)。架构沿用Godot4.6[场景组织与依赖注入](https://github.com/godotengine/godot-docs/blob/4.6/tutorials/best_practices/scene_organization.rst)，未新增Autoload、通用规则脚本语言或并行库存。
